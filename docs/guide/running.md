# 게임 실행

실행은 엔진에 프로젝트를 넘겨 게임을 시작하는 것입니다. 엔진은 프로젝트 폴더를 작업 디렉터리로 삼아 `game.json`을 읽고, 진입 스크립트를 실행합니다.

![게임 탭](images/game-tab.png)

## 실행 명령

| 명령 | 단축키 | 동작 |
|---|---|---|
| 실행 | F5 | 시작 씬부터 실행합니다 |
| 정지 | Shift+F5 | 엔진을 종료합니다 |
| 현재 씬부터 실행 | Ctrl+F5 | 열려 있는 씬부터 실행합니다. 맵 탭에서는 그 맵에서 실행합니다 |
| 다시 시작 | 실행 > 다시 시작 | 엔진을 종료하고 다시 실행합니다 |
| 리로드 | Ctrl+Shift+R | 게임 창을 유지한 채 핫 리로드를 실행합니다 |

엔진은 디스크에 저장된 파일을 읽습니다. 저장하지 않은 문서가 있으면 실행 전에 확인 창이 표시됩니다. Enter를 누르면 모두 저장한 뒤 실행합니다.

스크립트 언어는 `game.json`의 `script` 값으로 정해집니다. 도구 모음의 언어 목록이나 **실행 > 언어**에서 바꿉니다.

## 실행 방식

**도구 > 설정**의 **실행 방식**에서 선택합니다.

| 방식 | 정의 |
|---|---|
| 프로세스 (기본값) | 엔진 실행 파일을 별도 프로세스로 실행합니다. 게임은 별도 창에 표시됩니다. 배포하는 게임과 같은 실행 파일입니다 |
| 게임 탭 | 엔진의 WebAssembly 빌드를 에디터 안의 탭에서 실행합니다. 실행 전에 프로젝트 파일을 브라우저 메모리의 가상 파일 시스템에 복사합니다 |

웹판과 Windows 판은 항상 게임 탭을 사용합니다. 프로세스 방식에서 엔진 실행 파일을 찾지 못한 경우에도 게임 탭으로 실행합니다.

> **주의**: 게임 탭은 `resources/rtp/`, `*.zip`, `*.psd`, 32MB를 넘는 파일을 가상 파일 시스템에 복사하지 않습니다. 이 파일을 읽는 게임은 게임 탭에서 다르게 동작합니다.

### 게임 탭

- 게임 탭은 처음에 문서 영역 오른쪽에 열립니다. 다른 위치로 옮기면 다음부터 그 위치에 열립니다.
- 게임 화면을 클릭하면 키보드 입력이 게임으로 전달됩니다. F5, Shift+F5, Ctrl+F5, 리로드 단축키는 게임에 입력이 전달되는 중에도 에디터가 처리합니다.
- 위쪽에 실행 상태, 화면 크기와 배율, FPS가 표시됩니다.

> **주의**: 브라우저는 사용자가 페이지를 조작하기 전에는 소리를 재생하지 않습니다. 게임 탭 위쪽의 **소리 켜기**를 누르거나 게임 화면을 클릭해야 소리가 재생됩니다.

## 게임 루프

엔진은 다음 순서를 반복합니다.

1. 운영체제의 입력 이벤트를 읽습니다.
2. 앞 프레임 이후 지난 시간만큼 16ms 틱을 실행합니다. 틱마다 입력 상태를 갱신하고 진입 스크립트의 `update(16)`을 호출합니다. 한 프레임에 틱이 0번 실행될 수도, 여러 번 실행될 수도 있습니다.
3. 화면을 지우고 진입 스크립트의 `render`를 호출합니다.
4. 그린 화면을 표시합니다.

게임 상태는 틱 단위로 진행되므로, 화면 주사율과 관계없이 같은 시간 동안 같은 횟수만큼 갱신됩니다.

## 핫 리로드

핫 리로드는 게임 창을 유지한 채 스크립트 실행 환경을 다시 만드는 기능입니다. 게임 실행 중에 스크립트, 씬, 맵 파일을 저장하면(**저장 시 리로드**가 켜진 경우) 또는 리로드 명령을 실행하면 동작합니다.

처리 순서는 다음과 같습니다.

1. 에디터가 바뀐 파일을 엔진에 보냅니다. 엔진은 파일을 작업 디렉터리에 씁니다.
2. 현재 스크립트 실행 환경에서 진입 스크립트의 `Destroy`를 호출합니다. 템플릿 진입 스크립트는 이때 현재 씬을 닫으므로 모든 컴포넌트의 `destroy`가 호출됩니다.
3. 스크립트 실행 환경(Lua 상태 또는 mruby 상태)을 폐기합니다.
4. 새 실행 환경을 만들고 진입 스크립트를 처음부터 실행한 뒤 `Initialize`를 호출합니다.

콘솔에 핫 리로드 실행 기록이 표시됩니다.

| 항목 | 핫 리로드 후 |
|---|---|
| 전역 변수, 모듈 변수, `scene.state`, 컴포넌트 상태 | 모두 초기화됩니다 |
| 현재 씬 | 시작 씬부터 다시 시작합니다. **현재 씬부터 실행**으로 실행한 경우에는 그 씬부터 다시 시작합니다 |
| 게임 창, 오디오 장치 | 유지됩니다 |
| 스크립트가 해제하지 않은 엔진 자원(타일셋 이미지 등) | 유지됩니다 |

> **주의**: 핫 리로드는 게임 진행 상태를 유지하지 않습니다. 특정 장면을 반복해서 확인하려면 **현재 씬부터 실행**이나 맵의 **이 맵에서 실행**을 사용합니다.

> **주의**: 핫 리로드 중에 스크립트 오류가 발생하면, 스크립트가 멈추고 게임 창에는 아무것도 그려지지 않습니다. 오류를 수정해 다시 저장하면 스크립트가 다시 시작됩니다. 이전 실행 환경이 이미 오류로 멈춰 있었으면 `Destroy`가 호출되지 않으므로, 그 실행 환경의 `destroy` 처리는 실행되지 않습니다.

> **주의**: 스크립트 언어는 엔진을 시작할 때 정해집니다. `game.json`의 `script` 값을 바꾼 뒤에는 핫 리로드가 아니라 실행을 다시 시작해야 합니다.

## 콘솔과 오류

게임의 표준 출력(`print`)과 엔진 로그는 콘솔에 표시됩니다. 스크립트 오류는 다음 형식입니다.

```
Lua error in update: ./scripts/lua/components/player.lua:12: attempt to index a nil value
```

`파일:줄` 부분은 링크입니다. 클릭하면 해당 파일의 해당 줄이 열립니다. 비주얼 스크립팅으로 생성한 파일의 줄이면 그래프가 열리고 그 줄을 생성한 노드가 선택됩니다.

오류가 발생했을 때의 처리는 [스크립트](scripts.md#오류-처리)에서 설명합니다.

## 엔진 탐색 (데스크톱 앱)

프로세스 방식은 엔진 실행 파일을 다음 순서로 찾고, `--features` 옵션으로 실행해 엔진인지 확인합니다.

1. **도구 > 설정**의 **엔진 경로** (**실행 > 엔진 경로**에서도 지정)
2. 프로젝트의 `.initial-editor/engine` 파일에 적힌 경로
3. 프로젝트 안의 `build/Initial2D`
4. 앱에 포함된 엔진
5. 프로젝트와 같은 위치의 `../Initial2D/build/Initial2D`

현재 사용하는 엔진은 상태 표시줄과 **도움말 > InitialEditor 정보**에 표시됩니다.

> **주의**: 2, 3, 5번은 프로젝트 폴더가 지정하는 실행 파일입니다. 다른 사람에게 받은 프로젝트에 실행 파일이 들어 있으면 그 파일이 실행될 수 있으므로, 에디터는 처음 한 번 경로를 표시하고 실행 여부를 확인합니다. 허용한 기록은 **도구 > 설정**의 **찾은 엔진**에서 취소할 수 있습니다.

> **주의**: Ruby 프로젝트는 mruby가 포함된 엔진이 필요합니다. 엔진의 `--features` 출력에 `mruby`가 없으면 실행하지 않습니다.

## 안드로이드 스테이징

안드로이드 스테이징은 열린 프로젝트의 파일을 엔진 소스의 안드로이드 프로젝트 폴더(`android/app/src/main/assets/`)로 복사하는 작업입니다. **실행 > 안드로이드로 스테이징**으로 실행합니다. APK 빌드와 기기 설치는 하지 않으며, 완료 후 이어서 실행할 명령을 콘솔에 출력합니다.

- 엔진 소스 폴더(Initial2D 저장소), bash, python3이 필요합니다. Windows에서는 Git for Windows의 bash가 필요합니다.
- 엔진 소스 폴더는 **도구 > 설정**의 **엔진 저장소**에서 지정합니다. 비워 두면 자동으로 찾습니다.
- 복사 전에 확인 창에 파일 수와 크기가 표시됩니다.

> **주의**: 대상 폴더의 내용은 모두 교체됩니다. `config.setting`, 점(.)으로 시작하는 파일, `*.zip`, `*.psd`는 복사하지 않습니다.
