# 비주얼 스크립팅

그래프는 노드와 연결선으로 컴포넌트의 동작을 정의한 파일(`scripts/components/<경로>.graph.json`)입니다. 그래프를 저장하면 에디터가 같은 동작의 Lua 코드와 Ruby 코드를 생성합니다. 엔진은 그래프 파일을 읽지 않고 생성된 코드를 실행하므로, 그래프로 만든 컴포넌트는 직접 작성한 컴포넌트와 같은 방식으로 실행됩니다.

![그래프 편집 화면](images/graph-editor.png)

## 그래프 컴포넌트 만들기

1. **파일 > 새 그래프 컴포넌트**(Ctrl+Alt+G)를 선택하고 이름을 입력합니다. 예: `components/coin`
2. `scripts/components/coin.graph.json`이 만들어지고 그래프 편집기가 열립니다.
3. 씬의 오브젝트에 논리 이름 `components/coin`을 연결합니다 ([씬](scenes.md#컴포넌트-연결)). 인스펙터에서 이 이름을 클릭하면 그래프가 열립니다.

## 생성되는 파일

그래프를 저장할 때 오류가 없으면 다음 파일을 생성합니다.

| 파일 | 내용 |
|---|---|
| `scripts/lua/components/coin.lua` | Lua 컴포넌트 |
| `scripts/ruby/components/coin.rb` | Ruby 컴포넌트 |
| `scripts/components/coin.json` | 매개변수 선언 (매개변수가 있을 때) |

생성된 파일의 첫 줄은 `-- 그래프에서 만든 파일: <그래프 경로>`(Ruby는 `#`)입니다. 에디터는 이 줄로 생성된 파일을 구분합니다.

- 생성된 파일은 스크립트 편집기에서 읽기 전용으로 열립니다.
- 같은 경로에 첫 줄 표시가 없는 파일(직접 작성한 파일)이 있으면 그 파일을 덮어쓰지 않고 알림을 표시합니다. 그래프 편집기 위쪽의 **생성 파일 덮어쓰기**를 누르면 확인 후 덮어씁니다.
- 내용이 바뀌지 않은 파일은 다시 쓰지 않습니다.

> **주의**: 엔진은 생성된 파일만 실행합니다. 버전 관리 도구를 사용한다면 그래프 파일과 생성된 파일을 함께 커밋합니다. 생성된 파일이 없으면 에디터 없이 게임을 실행할 수 없습니다.

> **주의**: 생성된 파일을 다른 프로그램에서 수정해도, 첫 줄 표시가 남아 있으면 그래프를 다시 저장할 때 생성 코드로 덮어써집니다. 생성된 파일은 그래프에서만 수정합니다.

## 노드와 포트

노드는 하나의 동작이나 값입니다. 포트는 노드의 입력과 출력이며 두 종류가 있습니다.

| 포트 | 모양 | 의미 |
|---|---|---|
| 실행 포트 | 흰색 마름모 | 실행 순서입니다. 이벤트 노드에서 시작해 실행 연결선을 따라 차례로 실행됩니다 |
| 값 포트 | 색이 있는 원 | 값의 전달입니다. 색은 값의 형식(숫자, 문자열, 참거짓 등)을 나타냅니다 |

값 입력 포트가 연결되어 있지 않으면 노드 안의 입력란에 상수를 입력합니다. 연결하면 입력란은 숨겨지고 연결된 값이 사용됩니다.

### 노드 종류

| 분류 | 노드 |
|---|---|
| 이벤트 | init, update, render, destroy. 컴포넌트 함수에 해당합니다 |
| 흐름 | 조건 분기, 값 분기, 반복 |
| 변수 | 상태 읽기, 상태 쓰기, 변수 읽기, 변수 쓰기, 매개변수 |
| 오브젝트 | 이 오브젝트, 오브젝트 속성 읽기, 쓰기, props 읽기, 쓰기 |
| 씬 | 오브젝트 찾기, 오브젝트 제거, 씬 전환 |
| 수학, 논리, 텍스트 | 사칙연산, 난수, 범위 제한, 비교, 그리고, 또는, 부정, 텍스트 합치기, 콘솔 출력 |
| 엔진 API | 입력, 소리, 화면 크기 등 엔진 함수 |
| 라이브러리 | 노드 라이브러리에 정의된 함수와 상수 |

## 편집 조작

| 동작 | 조작 |
|---|---|
| 노드 추가 | 빈 곳을 오른쪽 클릭 또는 두 번 클릭. 또는 위쪽의 **노드 추가** |
| 연결 | 포트에서 다른 포트로 드래그 |
| 연결과 함께 노드 추가 | 포트에서 시작한 연결선을 빈 곳에서 놓기. 그 포트에 연결할 수 있는 노드만 목록에 표시됩니다 |
| 변수, 매개변수 노드 추가 | 옆 창의 항목 앞 ⠿ 아이콘을 캔버스로 드래그. 입력 포트 위에서 놓으면 노드를 만들고 그 포트에 연결합니다. 상태 필드와 지역 변수는 Alt를 누른 채 놓으면 쓰기 노드를 만듭니다 |
| 연결 해제 | 연결선을 오른쪽 클릭, 또는 Alt+포트 클릭 |
| 화면 이동 | 가운데 버튼 또는 오른쪽 버튼 드래그, Space+드래그 |
| 확대, 축소 | 마우스 휠 |
| 화면 맞춤 | F, 또는 위쪽의 **전체 보기** |
| 노드 정렬 | 위쪽의 **자동 정렬** |

복사, 붙여넣기, 복제, 삭제, 되돌리기는 편집 메뉴의 단축키로 실행합니다. 오른쪽 아래 미니맵을 클릭하면 그 위치로 이동합니다.

**메모**는 선택한 노드를 둘러싸는 사각형과 설명 글입니다. 노드를 선택하고 위쪽의 **메모**를 누르면 만들어집니다. 메모의 제목 줄을 드래그하면 안의 노드가 함께 이동합니다. 메모는 생성 코드에 포함되지 않습니다.

## 옆 창

| 항목 | 정의 |
|---|---|
| 상태 필드 | 실행 중 계속 유지되는 값입니다. 기본 저장 위치는 `scene.state`이며, 상태 표를 반환하는 라이브러리 함수로 바꿀 수 있습니다 |
| 지역 변수 | 함수가 한 번 실행되는 동안만 유지되는 값입니다 |
| 매개변수 | 씬 인스펙터에서 오브젝트마다 지정하는 값입니다. 매개변수 선언 파일로 생성됩니다 |
| 노드 라이브러리 | 이 그래프에서 사용할 `*.nodes.json` 파일 목록입니다 |
| 문제 | 그래프 검사에서 발견된 오류와 경고입니다. 항목을 클릭하면 해당 노드로 이동합니다 |

노드를 선택하면 그 노드의 설정도 옆 창에 표시됩니다.

> **주의**: 상태 필드의 기본 저장 위치는 `scene.state`입니다. `scene.state`는 같은 씬의 모든 컴포넌트가 공유하므로, 같은 그래프 컴포넌트를 여러 오브젝트에 연결하면 상태 필드 값도 공유됩니다. 오브젝트마다 다른 값이 필요하면 오브젝트 속성이나 props를 사용합니다.

### 매개변수를 노드 입력에 연결하는 예

오브젝트마다 다른 효과음을 재생하는 경우입니다.

1. 옆 창 **매개변수**에서 **추가**를 누르고 이름을 `sound`, 형식을 `string`으로 지정합니다. 기본값으로 `./resources/audio/flap.wav`를 입력합니다.
2. `sound` 항목 앞의 ⠿ 아이콘을 효과음 재생 노드의 **파일 경로** 포트 위로 드래그합니다. 매개변수 노드가 만들어지고 파일 경로에 연결됩니다.
3. 씬 인스펙터에서 오브젝트마다 `sound` 값을 지정합니다.

생성 코드는 실행 시점에 매개변수 값을 읽습니다(Lua `params.sound`, Ruby `@params["sound"]`). 코드는 하나이고, 값만 오브젝트마다 다릅니다.

## 검사와 오류

그래프 검사는 저장 전에 그래프의 오류를 찾는 과정입니다. 비어 있는 필수 입력, 형식이 맞지 않는 연결, 존재하지 않는 변수나 함수, 비어 있거나 폴더를 가리키는 파일 경로 등을 오류로 표시합니다.

- 오류가 있으면 코드를 생성하지 않습니다. 이전에 생성한 파일은 그대로 남습니다.
- 오류가 있는 노드는 테두리 색으로 표시됩니다.
- 이벤트 노드와 연결되지 않은 실행 노드는 코드에 포함되지 않으며 경고로 표시됩니다.

게임 실행 중 생성된 파일에서 오류가 발생하면, 콘솔의 오류 줄을 클릭했을 때 그래프가 열리고 그 줄을 생성한 노드가 선택됩니다.

> **주의**: 그래프에 오류가 있는 동안 저장하면 그래프 파일만 저장되고 생성 코드는 이전 상태로 남습니다. 게임은 이전 코드로 실행되므로, 저장 후 그래프 편집기 위쪽의 상태(오류 없음, 생성 코드 저장됨)를 확인합니다.

## 노드 라이브러리

노드 라이브러리는 직접 작성한 스크립트 모듈의 함수와 상수를 노드로 사용하기 위한 정의 파일(`*.nodes.json`)입니다. 파일에는 모듈의 Lua 이름, Ruby 이름, 함수의 인자와 반환 형식, 상수를 적습니다. 옆 창의 **노드 라이브러리**에 파일 경로를 입력해 추가합니다. 생성 코드에서는 Lua `flappy.GRAVITY`, Ruby `FlappyCommon::GRAVITY`처럼 각 언어의 이름으로 호출됩니다.

> **주의**: 노드 라이브러리 파일은 모듈의 실제 코드와 별도로 관리됩니다. 모듈의 함수 이름이나 인자를 바꾸고 라이브러리 파일을 수정하지 않으면, 그래프 검사는 통과하지만 실행할 때 오류가 발생합니다.
