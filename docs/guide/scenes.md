# 씬

씬은 한 화면을 구성하는 오브젝트 목록을 담은 JSON 파일입니다. 경로는 `resources/scenes/<이름>.json`입니다. 엔진은 씬 파일 형식을 직접 읽지 않습니다. 진입 스크립트가 씬 로더(`scripts/lua/scene_loader.lua` 또는 `scripts/ruby/scene_loader.rb`)를 호출하고, 씬 로더가 파일을 읽어 오브젝트와 컴포넌트를 만듭니다.

![씬 편집 화면](images/scene-editor.png)

## 씬 파일 구조

```json
{
  "version": 1,
  "name": "main",
  "objects": [
    { "id": "player", "type": "sprite", "x": 100, "y": 200, "visible": true,
      "props": { "image": "resources/player.png", "frames": 4 },
      "scripts": ["components/player"],
      "params": { "components/player": { "speed": 120 } } }
  ]
}
```

| 키 | 의미 |
|---|---|
| `version` | 형식 버전. 1이어야 합니다 |
| `name` | 씬 이름 |
| `objects` | 오브젝트 목록. 목록 순서가 갱신 순서이자 그리는 순서입니다 |
| `id` | 씬 안에서 고유한 오브젝트 이름. 스크립트는 이 값으로 오브젝트를 찾습니다 |
| `type` | 오브젝트 종류: `node`(빈 노드), `sprite`, `text`, `tilemap` |
| `x`, `y` | 논리 좌표의 위치(픽셀). 생략하면 0입니다 |
| `visible` | 표시 여부. 생략하면 `true`입니다 |
| `props` | 종류별 속성 |
| `scripts` | 연결된 컴포넌트의 논리 이름 목록. 목록 순서대로 호출됩니다 |
| `params` | 컴포넌트별 매개변수 값 |

## 오브젝트 종류

| 종류 | 정의 | 주요 속성 |
|---|---|---|
| 빈 노드 (`node`) | 화면에 아무것도 그리지 않는 오브젝트입니다. 컴포넌트를 실행하는 데만 사용합니다 (점수 관리, 적 생성 등) | 없음 |
| 스프라이트 (`sprite`) | 이미지 파일의 한 프레임을 그리는 오브젝트입니다 | `image`, `width`, `height`, `frames`, `frameDelay`, `startFrame`, `endFrame`, `loop`, `scale`, `angle`, `opacity` |
| 텍스트 (`text`) | 비트맵 글꼴로 문자열을 그리는 오브젝트입니다 | `text`, `font` |
| 타일맵 (`tilemap`) | 맵 파일의 레이어를 그리는 오브젝트입니다 | `map`, `groundLayers` |

스프라이트와 텍스트의 출력 방식, 알파 채널 처리는 [이미지와 텍스트 출력](graphics.md)에서 설명합니다.

## 편집

### 씬과 오브젝트 만들기

- 새 씬: **씬 > 새 씬**(Ctrl+Shift+N)
- 오브젝트 추가: **씬 > 오브젝트 추가**에서 종류를 선택하거나, Ctrl+Shift+A로 목록에서 선택
- 시작 씬 지정: 씬을 연 상태에서 **씬 > 시작 씬으로 지정**, 또는 도구 모음의 씬 목록. `game.json`의 `startScene` 값이 바뀝니다

### 씬 뷰 조작

| 조작 | 동작 |
|---|---|
| 클릭 | 오브젝트 선택 |
| 빈 곳에서 드래그 | 사각형 영역 안의 오브젝트 선택 |
| 선택한 오브젝트를 드래그 | 이동 |
| 방향키 | 1픽셀 이동. Shift를 누르면 10픽셀 |
| Esc | 선택 해제 |
| 가운데 버튼 드래그, 오른쪽 버튼 드래그, Space+드래그 | 화면 이동 |
| 마우스 휠 | 확대, 축소. Shift 또는 Alt를 누르면 화면 이동 |
| Ctrl+=, Ctrl+-, Ctrl+0 | 확대, 축소, 100% |

씬 뷰 위쪽의 도구 모음에서 격자, 격자 크기, 스냅, 줌, **카메라에 맞추기**를 설정합니다. 씬 뷰의 카메라 사각형은 게임의 논리 화면 영역이며, 크기는 `game.json`의 창 크기와 렌더 배율로 정해집니다.

편집 메뉴의 복사(Ctrl+C), 붙여넣기(Ctrl+V), 복제(Ctrl+D), 삭제(Delete)는 선택한 오브젝트에 적용됩니다. 모든 편집은 Ctrl+Z로 되돌릴 수 있습니다.

> **주의**: 씬 뷰는 씬 파일에 저장된 초기 상태만 표시합니다. 컴포넌트가 실행 중에 바꾸는 위치, 속성, 새로 만드는 오브젝트는 표시되지 않습니다. 실행 결과는 **실행 > 현재 씬부터 실행**(Ctrl+F5)으로 확인합니다.

### 계층 패널

계층 패널은 `objects` 목록을 순서대로 표시합니다. 목록 위쪽의 오브젝트가 먼저 그려지므로, 아래쪽 오브젝트가 화면에서 앞에 표시됩니다.

- 항목을 드래그해 순서를 바꿉니다.
- 눈 아이콘은 `visible` 값을 바꿉니다.
- F2, Enter, 두 번 클릭으로 `id`를 바꿉니다.

> **주의**: `id`는 씬 안에서 고유해야 합니다. 중복된 `id`가 있으면 씬 로더가 씬을 열지 않고 오류를 냅니다. 스크립트에서 `scene:find("id")`로 찾는 오브젝트의 `id`를 바꾸면 그 스크립트도 함께 수정해야 합니다.

### 인스펙터

인스펙터는 선택한 오브젝트의 공통 속성(id, x, y, 표시), 종류별 속성, 컴포넌트 목록, 검사 결과를 표시합니다. 검사 결과는 씬 로더가 씬을 열 때 오류로 처리할 항목(중복 id, 비어 있는 이미지 경로, 선언과 맞지 않는 매개변수, 열 수 없는 맵 파일 등)입니다.

## 컴포넌트 연결

컴포넌트는 오브젝트에 연결하는 스크립트 모듈입니다. 작성 방법은 [스크립트](scripts.md)에서 설명합니다.

1. 오브젝트를 선택하고 인스펙터의 **스크립트 추가**를 누릅니다.
2. 논리 이름을 입력합니다. 예: `components/player`는 Lua 프로젝트에서 `scripts/lua/components/player.lua`를 가리킵니다.
3. **파일이 없으면 생성**을 켜면 기본 함수 정의가 들어 있는 파일을 만듭니다.

한 오브젝트에 연결된 컴포넌트는 `scripts` 목록 순서대로 호출됩니다. 인스펙터의 위, 아래 화살표로 순서를 바꿉니다.

## 매개변수

매개변수는 같은 컴포넌트를 사용하는 오브젝트마다 다르게 지정하는 값입니다. 항목은 선언 파일 `scripts/components/<논리 이름>.json`에 정의하고, 값은 씬 파일의 `params`에 저장합니다. Lua와 Ruby가 같은 선언 파일을 사용합니다.

```json
{
  "version": 1,
  "fields": [
    { "key": "speed", "type": "number", "label": "속도", "default": 60, "min": 0 },
    { "key": "target", "type": "object", "label": "대상" }
  ]
}
```

| type | 값의 형식 | 인스펙터 입력 |
|---|---|---|
| `string`, `text` | 문자열 | 한 줄 입력란, 여러 줄 입력란 |
| `number`, `integer` | 숫자, 정수 (`min`, `max`로 범위 지정) | 숫자 입력란 |
| `boolean` | 참, 거짓 | 체크 상자 |
| `enum` | `values` 중 하나 | 목록 |
| `object` | 같은 씬의 다른 오브젝트 `id` | 목록 |

씬 파일에는 기본값과 다른 값만 저장됩니다. **기본값 복원**은 저장된 값을 지웁니다. 선언 파일이 없으면 **매개변수 선언 만들기**가 현재 값의 형식으로 선언 파일을 만듭니다.

스크립트는 매개변수를 다음과 같이 받습니다.

```lua
-- Lua: 각 함수의 마지막 인자
function Mover.update(obj, scene, elapsed, params)
  obj.x = obj.x + params.speed * elapsed / 1000
end
```

```ruby
# Ruby: initialize 의 인자 (문자열 키 Hash)
class Mover
  def initialize(params = {})
    @speed = params["speed"]
  end
end
```

> **주의**: 기본값(`default`)이 없는 항목에 씬 값도 없으면 해당 키는 매개변수에 들어 있지 않습니다. Lua에서는 `nil`, Ruby에서는 `nil`이 됩니다. 이 값을 그대로 엔진 함수에 넘기면 오류가 발생하므로, 기본값을 지정하거나 스크립트에서 `nil`을 확인합니다.

> **주의**: 씬 로더 파일이 매개변수를 전달하지 않는 버전이면, 인스펙터에 **씬 로더 교체** 안내가 표시됩니다. 교체하면 에디터에 포함된 씬 로더로 파일을 덮어씁니다. 씬 로더 파일을 직접 수정한 경우 그 수정 내용은 사라집니다.

## 타일맵 오브젝트

타일맵 오브젝트는 맵 파일을 씬에 표시합니다. **씬 > 오브젝트 추가 > 타일맵**으로 추가하고 인스펙터에서 `map`(맵 파일)을 선택합니다. 맵 파일 형식은 [맵](maps.md)에서 설명합니다.

| 속성 | 의미 |
|---|---|
| `map` | 맵 파일 경로 (필수) |
| `groundLayers` | 다른 오브젝트보다 먼저 그릴 레이어 수 (0 이상, 기본값 1) |

맵의 앞쪽 `groundLayers`개 레이어는 모든 오브젝트보다 먼저 그려지고, 나머지 레이어는 모든 오브젝트와 컴포넌트의 `render` 출력보다 나중에 그려집니다. 타일맵 오브젝트의 목록 위치와 관계없이 이 순서가 적용됩니다. 맵은 오브젝트 위치(x, y, 소수점 이하 버림)를 왼쪽 위 모서리로 하여 그려집니다.

> **주의**: `groundLayers`보다 뒤의 레이어는 텍스트를 포함한 모든 오브젝트 위에 그려집니다. 점수 같은 화면 표시가 맵의 윗 레이어에 가려질 수 있습니다. `groundLayers`를 0으로 지정하면 모든 레이어가 오브젝트 위에 그려집니다.

> **주의**: 맵 파일을 읽지 못하면 씬 전체를 열 수 없습니다. 오류는 `scene: tilemap '<id>': cannot load <맵 경로> (...)` 형식이고 게임이 종료 코드 1로 끝납니다.

씬 뷰에서는 타일맵을 한 번 클릭해 선택한 뒤에만 드래그로 이동할 수 있습니다. 선택하지 않은 타일맵 위에서 드래그하면 영역 선택이 됩니다. 인스펙터의 **맵 열기**는 맵 파일을 맵 뷰로 엽니다.

## 동작 방식

### 씬 열기

진입 스크립트는 `SceneLoader.open(이름)`으로 씬을 엽니다. 처리 순서는 다음과 같습니다.

1. **경로 결정**: 이름에 `/`가 없고 `.json`으로 끝나지 않으면 `./resources/scenes/<이름>.json`을 읽습니다. 그렇지 않으면 인자를 경로로 사용합니다.
2. **읽기**: JSON 파일을 읽습니다. 파일이 없거나 형식이 잘못되면 `scene: cannot open scene <경로> (...)` 오류가 발생합니다.
3. **검사**: 버전, 이름, 오브젝트 목록, 각 오브젝트의 속성, 매개변수를 순서대로 검사하고 첫 번째 문제에서 멈춥니다. 이 단계에서는 이미지, 글꼴, 맵, 컴포넌트 파일을 열지 않습니다.
4. **생성**: 목록 순서대로 오브젝트를 하나씩 만듭니다. 기본값을 채우고, 스프라이트의 이미지를 읽고, 텍스트의 글꼴을 준비하고, 컴포넌트 모듈을 불러오고, 매개변수 표를 만듭니다.
5. **초기화**: 모든 오브젝트를 만든 다음, 목록 순서대로 각 오브젝트의 컴포넌트 `init`을 `scripts` 순서대로 호출합니다.

> **주의**: 이름에 `/`가 들어 있으면 경로로 해석됩니다. `levels/one`은 `./resources/scenes/levels/one.json`이 아니라 `./levels/one`을 읽습니다. 하위 폴더의 씬은 `resources/scenes/levels/one.json`처럼 전체 경로로 지정합니다.

> **주의**: `init` 시점에는 같은 씬의 모든 오브젝트가 이미 존재합니다. 따라서 `init`에서 `scene:find`로 다른 오브젝트를 찾을 수 있습니다. 단, 다른 오브젝트의 `init`이 아직 실행되지 않았을 수 있으므로, 그 오브젝트가 `init`에서 설정하는 값에 의존하지 않습니다.

### 한 틱의 처리 순서

엔진은 16ms마다 진입 스크립트의 `update`를 호출하고, 진입 스크립트는 `scene:tick(elapsed)`를 호출합니다.

1. **갱신**: 틱 시작 시점의 오브젝트 목록을 순서대로 처리합니다. 각 오브젝트의 컴포넌트 `update(obj, scene, elapsed, params)`를 `scripts` 순서대로 호출합니다. `visible`이 `false`인 오브젝트도 갱신됩니다.
2. **스프라이트 반영**: 모든 갱신이 끝난 뒤, 각 스프라이트에 `x`, `y`, `visible`, `opacity`, `scale`, `angle`을 적용하고 애니메이션 프레임을 진행합니다.
3. **씬 전환**: 전환이 예약되어 있으면 전환을 실행합니다 (아래 설명).

`scene:spawn(spec)`으로 만든 오브젝트는 그 자리에서 `init`이 호출되고, 다음 틱부터 `update`가 호출됩니다. `scene:remove(id)`는 그 자리에서 해당 오브젝트의 `destroy`를 호출하고 이미지를 해제한 뒤 목록에서 제거합니다.

### 그리기 순서

엔진은 프레임마다 진입 스크립트의 `render`를 호출하고, 진입 스크립트는 `scene:draw()`를 호출합니다.

1. 타일맵 오브젝트의 바닥 레이어(`groundLayers`)를 그립니다.
2. `visible`이 `true`인 오브젝트를 목록 순서대로 처리합니다. 오브젝트를 그린 직후 그 오브젝트의 컴포넌트 `render`를 `scripts` 순서대로 호출합니다.
3. 타일맵 오브젝트의 나머지 레이어를 그립니다.

> **주의**: `visible`이 `false`인 오브젝트는 그려지지 않고, 그 오브젝트의 컴포넌트 `render`도 호출되지 않습니다. 화면에 무언가를 그리는 컴포넌트를 숨겨진 빈 노드에 연결하면 아무것도 표시되지 않습니다.

### 씬 전환

`scene:switch(이름)`은 다른 씬으로 바꾸도록 예약하는 함수입니다. 호출 즉시 씬이 바뀌지 않습니다.

1. **예약**: `switch`는 전환할 씬 이름만 기록합니다. 이름이 올바른지는 이 시점에 검사하지 않습니다. 같은 틱에 여러 번 호출하면 마지막 호출의 이름이 사용됩니다.
2. **남은 갱신**: 예약한 뒤에도 그 틱의 나머지 처리가 계속됩니다. 목록에서 뒤에 있는 오브젝트의 `update`가 호출되고, 스프라이트 반영도 실행됩니다.
3. **현재 씬 닫기**: 틱의 마지막 단계에서 현재 씬을 닫습니다. 목록 순서대로 각 오브젝트의 컴포넌트 `destroy`를 `scripts` 순서대로 호출하고, 스프라이트와 이미지를 해제합니다.
4. **새 씬 열기**: 같은 틱 안에서 새 씬을 엽니다. 위의 "씬 열기" 순서(경로 결정, 읽기, 검사, 생성, 초기화)를 그대로 따릅니다.
5. **다음 프레임**: 중간에 빈 프레임을 그리지 않습니다. 다음에 그려지는 프레임은 새 씬입니다.

`update`에서 `switch`를 호출하면 같은 틱의 끝에서 전환됩니다. `init`이나 `render`에서 호출하면 다음 틱의 끝에서 전환됩니다.

전환 전후로 유지되는 것과 유지되지 않는 것은 다음과 같습니다.

| 항목 | 전환 후 |
|---|---|
| 오브젝트, 컴포넌트 인스턴스 | 모두 해제되고 새 씬의 것으로 바뀝니다 |
| `scene.state` | 새 씬에서 빈 표로 시작합니다. 이전 씬의 값은 전달되지 않습니다 |
| 스프라이트 이미지 | 해제됩니다. 새 씬에서 같은 이미지를 쓰면 파일을 다시 읽습니다 |
| 전역 변수, 모듈 변수 | 유지됩니다. 스크립트 실행 환경이 계속 실행되기 때문입니다 |

> **주의**: 씬 사이에 값(점수, 선택한 캐릭터 등)을 넘기려면 `scene.state`가 아니라 전역 변수나 모듈 변수를 사용합니다. 단, 이 값은 핫 리로드 때 사라집니다.

> **주의**: 존재하지 않는 씬 이름으로 전환하면, 현재 씬을 이미 닫은 뒤 새 씬을 여는 단계에서 오류가 발생합니다. 오류는 `Lua error in update: scene: cannot open scene ./resources/scenes/<이름>.json (...)` 형식이고 게임이 종료 코드 1로 끝납니다. 새 씬의 검사 오류도 같은 방식으로 처리됩니다.

> **주의**: 전환이 프레임의 마지막 틱에서 일어나면, 새 씬은 첫 `update` 전에 한 번 그려집니다. 이때 스프라이트는 생성 시점의 값으로 그려지고, `init`에서 바꾼 위치나 속성은 다음 틱에 반영됩니다. 위치를 정하는 값은 `init`보다 씬 파일에 지정하는 것이 안전합니다.

### 오류

씬 로더의 오류 메시지는 `scene: `로 시작합니다. 시작할 때 씬을 열지 못하면 `Lua error in init: scene: ...`이 출력되고 게임이 종료 코드 1로 끝납니다. 컴포넌트 함수에서 발생한 오류는 [스크립트](scripts.md#오류-처리)에서 설명합니다.
