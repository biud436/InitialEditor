# 이미지와 텍스트 출력

이 문서는 스프라이트(이미지)와 텍스트가 화면에 그려지는 과정을 설명합니다. 아래 내용은 SDL2 렌더러를 쓰는 엔진(macOS, Linux, Android, 웹)의 동작입니다.

## 좌표계와 화면 크기

- 원점은 게임 화면의 왼쪽 위입니다. x는 오른쪽, y는 아래쪽으로 증가합니다.
- 단위는 논리 픽셀입니다. 논리 화면 크기는 `game.json`의 창 크기(`windowWidth`, `windowHeight`)를 렌더 배율(`renderScale`)로 나눈 값입니다. 예를 들어 창이 768x896이고 렌더 배율이 2이면 논리 화면은 384x448입니다.
- 엔진은 논리 화면을 창 크기에 맞게 확대해 출력합니다. 확대할 때 보간하지 않고 가장 가까운 픽셀을 사용합니다(최근접 이웃 필터). 픽셀 아트의 경계가 흐려지지 않습니다.
- 스프라이트와 텍스트에는 카메라 변환이 없습니다. 오브젝트의 x, y가 그대로 화면 좌표입니다. 화면을 스크롤하려면 스크립트에서 오브젝트의 위치를 옮깁니다.
- 매 프레임 창 전체를 검은색으로 지운 뒤, 게임 화면 영역을 흰색으로 채우고 그립니다.

> **주의**: 렌더 배율은 1~16의 정수로 처리되고(2.5는 2), 논리 화면 크기는 정수 나눗셈의 몫입니다. 창 크기가 배율로 나누어떨어지지 않으면 확대 비율이 정수가 아니게 되어 픽셀 크기가 고르지 않게 보일 수 있습니다. 창 크기는 배율의 배수로 지정합니다.

> **주의**: Android에서는 화면 비율에 맞추기 위해 논리 화면의 너비가 늘어날 수 있습니다. 화면 오른쪽 끝을 기준으로 배치하는 요소는 실제 논리 너비(`WindowWidth()`)를 읽어 계산합니다.

## 이미지 출력

이미지 출력은 이미지 파일을 읽어 텍스처로 변환하고, 스프라이트 속성(프레임, 위치, 배율, 회전, 불투명도)을 적용해 렌더러에 그리기 명령을 보내는 과정입니다.

### 1. 파일 읽기와 텍스처 생성

1. 스프라이트를 만들 때 `props.image`의 파일을 읽습니다. 경로는 프로젝트 폴더 기준입니다.
2. 읽은 이미지를 RGBA 32비트 형식으로 변환합니다.
3. 변환한 이미지로 텍스처를 만들고, 혼합 방식을 알파 혼합으로 설정합니다.

같은 씬에서 같은 이미지를 쓰는 스프라이트는 텍스처 하나를 공유합니다. 그 이미지를 쓰는 마지막 스프라이트가 제거되거나 씬이 닫히면 텍스처가 해제됩니다.

| 형식 | 지원 |
|---|---|
| PNG | 모든 플랫폼에서 지원합니다. 권장 형식입니다 |
| JPG | 지원합니다. 알파 채널이 없습니다 |
| BMP 등 그 밖의 형식 | 웹판에서는 읽을 수 없습니다. 데스크톱에서도 플랫폼의 이미지 라이브러리 구성에 따라 다릅니다 |

> **주의**: `width`나 `height`를 0으로 두면 씬 로더가 PNG 파일 헤더에서 크기를 읽습니다. PNG가 아닌 이미지에서 크기를 0으로 두면 씬을 열 때 오류가 발생합니다.

### 2. 알파 채널

- PNG의 알파 채널은 그대로 유지됩니다. 각 픽셀의 알파 값이 화면과 혼합되는 비율을 결정합니다.
- 혼합 방식은 일반 알파 혼합(`결과 = 원본 × 알파 + 배경 × (1 - 알파)`)입니다. 미리 곱한 알파(premultiplied alpha)는 사용하지 않습니다.
- 스프라이트와 타일맵에는 색상 키가 없습니다. 특정 색(마젠타, 검정 등)을 투명색으로 처리하지 않습니다. 투명하게 할 부분은 이미지 파일의 알파 값을 0으로 만들어야 합니다.
- `opacity`(0~255)는 픽셀의 알파 값에 곱해집니다. 실제 알파는 `픽셀 알파 × opacity / 255`입니다. `opacity`가 128이면 원래 불투명하던 픽셀은 반투명이 되고, 원래 반투명하던 픽셀은 더 투명해집니다.

> **주의: 이미지 형식별 투명도 처리**
>
> - **RGBA PNG (32비트)**: 픽셀마다 알파 값이 적용됩니다. 가장 안전한 형식입니다.
> - **RGB PNG (24비트), JPG**: 알파 채널이 없으므로 모든 픽셀이 불투명합니다. 배경색이 그대로 보입니다.
> - **팔레트 PNG (8비트)와 tRNS 투명색**: RGBA로 변환하는 과정은 이미지 라이브러리가 처리합니다. 결과가 기대와 다를 수 있으므로 RGBA PNG로 저장해 사용합니다.
> - **배경색으로 투명도를 표시한 이미지**: 일부 게임 제작 도구의 소재는 특정 배경색을 투명색으로 씁니다. 이 엔진은 색상 키를 적용하지 않으므로, 이런 이미지는 배경색을 알파 0으로 바꾼 뒤 사용합니다.
> - **반투명 가장자리**: 확대할 때 보간하지 않으므로, 가장자리의 반투명 픽셀도 그대로 확대되어 보입니다.

### 3. 프레임

스프라이트 이미지는 같은 크기의 프레임을 가로 한 줄로 이어 붙인 형식입니다. 프레임 i(0부터 시작)는 이미지의 `x = i × width`, `y = 0` 위치에서 `width × height` 크기로 잘라 그립니다. 프레임 사이 간격은 없고, 둘째 줄 이하는 사용하지 않습니다.

| 속성 | 의미 | 기본값 |
|---|---|---|
| `width`, `height` | 프레임 한 장의 크기. 0이면 이미지 너비를 `frames`로 나눈 값과 이미지 높이 | 0 |
| `frames` | 프레임 수 | 1 |
| `startFrame`, `endFrame` | 재생할 프레임 범위 (0부터, `endFrame` 포함) | 0, 0 |
| `frameDelay` | 다음 프레임으로 넘어가는 시간(ms) | 100 |
| `loop` | `true`면 반복, `false`면 `endFrame`에서 정지 | `true` |

- `endFrame`이 0이거나 `startFrame`보다 작으면 `startFrame` 한 장만 표시합니다.
- 프레임은 누적 시간이 `frameDelay`보다 커질 때 다음으로 넘어갑니다. 한 틱(16ms)에 최대 한 프레임만 넘어가므로, `frameDelay`를 16보다 작게 지정해도 초당 약 60프레임보다 빨라지지 않습니다.
- 스크립트에서 `obj.animate = false`로 두면 프레임 진행이 멈춥니다. 위치, 배율, 회전은 계속 적용됩니다.

### 4. 위치, 배율, 회전

- `x`, `y`는 회전하기 전 프레임의 왼쪽 위 모서리 위치입니다.
- `scale`은 왼쪽 위 모서리를 기준으로 오른쪽, 아래쪽으로 크기를 바꿉니다.
- `angle`은 도 단위이며 양수가 시계 방향입니다. 회전 중심은 프레임의 왼쪽 위 모서리입니다.

> **주의**: 회전 중심이 가운데가 아니므로, 이미지를 제자리에서 돌리려면 회전에 맞춰 `x`, `y`도 함께 옮겨야 합니다.

> **주의**: 좌우 반전을 지원하지 않습니다. `scale`에 음수를 지정하면 반전이 아니라 180도 회전으로 처리됩니다. 왼쪽과 오른쪽을 보는 모습이 필요하면 각각의 프레임을 이미지에 그려 둡니다.

### 5. 그리기

씬 로더는 매 틱 끝에 오브젝트의 `x`, `y`, `visible`, `opacity`, `scale`, `angle`을 스프라이트에 적용하고, 프레임마다 목록 순서대로 그립니다. 그리는 순서는 [씬](scenes.md#그리기-순서)에서 설명합니다.

> **주의**: 스크립트에서 바꾼 위치와 속성은 그 틱이 끝날 때 스프라이트에 적용됩니다. 씬을 연 직후 첫 `update` 전에 그려지는 프레임에서는 `init`에서 바꾼 값이 아직 적용되지 않을 수 있습니다.

## 텍스트 출력

텍스트 출력은 비트맵 글꼴 파일에서 글자 이미지의 위치를 찾아, 글자마다 글꼴 이미지의 해당 영역을 화면에 복사하는 과정입니다.

### 글꼴 파일

- 형식은 BMFont의 XML `.fnt` 파일과 글꼴 이미지(PNG)입니다. `.fnt` 파일은 각 글자의 이미지 내 위치, 크기, 간격을 정의합니다.
- 글꼴 이미지는 `.fnt` 파일의 위치와 관계없이 `resources/fonts/` 폴더에서 읽습니다.
- 템플릿에는 `resources/fonts/hangul.fnt`(32픽셀, 줄 높이 32)가 포함되어 있습니다.

### 그리기 방식

- 글자 색은 글꼴 이미지에 그려진 색 그대로입니다. 텍스트에 색, 배율, 회전, 불투명도를 지정할 수 없습니다.
- 줄바꿈 문자(`\n`)는 시작 x 위치로 돌아가 줄 높이만큼 아래로 이동합니다.
- 텍스트의 x, y는 정수로 잘려서 사용됩니다.

> **주의: 글꼴 이미지의 투명색**
>
> 텍스트를 그릴 때는 글꼴 이미지의 순수한 검정(RGB 0, 0, 0) 픽셀을 투명하게 처리합니다. 이 처리는 텍스트에만 적용되고 스프라이트에는 적용되지 않습니다. 검정 외곽선이 있는 글꼴을 만들면 외곽선이 사라지므로, 외곽선은 (1, 1, 1)처럼 순수한 검정이 아닌 색으로 칠합니다.

> **주의: 표시할 수 없는 글자**
>
> - 그릴 수 있는 문자 범위는 코드 32~255와 완성형 한글 음절(U+AC00~U+D7A3)입니다. 이 범위 밖의 문자(한글 자모 ㄱ, 한자, 탭, 이모지)는 그려지지 않습니다.
> - 범위 안이라도 `.fnt`에 정의되지 않은 글자는 너비 없이 생략됩니다. 빈칸이 생기지 않고 앞뒤 글자가 붙어서 표시됩니다.
> - `hangul.fnt`에는 ASCII 문자와 KS X 1001 완성형 2,350자만 들어 있습니다. 그 밖의 음절(예: 똠, 뷁)은 표시되지 않습니다.

> **주의: 글꼴은 한 번에 하나**
>
> 엔진은 글꼴을 하나만 유지합니다. 씬 로더는 텍스트를 그리기 전에 그 텍스트의 글꼴이 현재 글꼴과 다르면 글꼴 파일을 다시 읽습니다. 한 씬에서 서로 다른 글꼴을 쓰는 텍스트가 있으면 매 프레임 글꼴 파일을 반복해서 읽으므로 속도가 크게 떨어집니다. 한 씬에서는 글꼴 하나만 사용합니다.

> **주의**: `props.font`를 비워 두면 글꼴을 읽지 않습니다. 이전에 준비된 글꼴이 있으면 그 글꼴로, 없으면 아무것도 그리지 않습니다. 텍스트 오브젝트에는 글꼴을 항상 지정합니다.

> **주의**: 글꼴 이미지 파일을 읽지 못해도 오류가 발생하지 않습니다. 이 경우 텍스트가 표시되지 않으므로, 글꼴 이미지가 `resources/fonts/`에 있는지 확인합니다.
