# 02. 범위, 장르, 화면, 기능, 테마

> 결정: **장르 중립 코어 + 확장.** 코어는 프로젝트, 자산, 씬과 오브젝트, 스크립트, 실행, 콘솔, 테마까지 안다.
> 타일맵과 RPG는 확장이다. 화면은 도킹 패널 여섯으로 시작하고 레이아웃은 저장된다.

## 1. 장르: 코어와 확장의 경계

엔진의 판단 기준을 그대로 쓴다. **"이 기능이 플래피버드에도 말이 되는가?"** 말이 되면 코어, 안 되면 확장.

| 기능 | 자리 | 플래피버드에도 말이 되는가 |
|---|---|---|
| 프로젝트 열기, 파일 트리, 자산 미리보기(이미지, 오디오 재생, 폰트) | 코어 | 된다 |
| 스크립트 편집, 저장, 핫 리로드, 실행과 정지, 콘솔 | 코어 | 된다. 플래피버드는 스크립트가 전부다 |
| 씬과 오브젝트(빈 노드, 스프라이트, 글자), 계층, 인스펙터, 선택과 이동, 격자와 스냅, 되돌리기 | 코어 | 된다. 새와 파이프와 점수 글자가 오브젝트다 |
| 스크립트 컴포넌트(오브젝트에 스크립트 붙이기) | 코어 | 된다. 새의 낙하 물리가 컴포넌트다 |
| 스프라이트 시트 프레임 구간 편집 | 코어 (후보) | 된다. 새의 날갯짓 |
| 타일맵(타일셋, 레이어, 그리기 도구, 통행) | **확장** `ext-tilemap` | 안 된다 |
| 이벤트 배치, 커맨드 편집, 데이터베이스(아이템, 적) | **확장** `ext-rpg` | 안 된다 |
| 오토타일 | 확장 `ext-tilemap` | 안 된다 |

확장은 코어의 등록 API로 들어온다 ([04-extensions-and-tilemap.md](04-extensions-and-tilemap.md)). 처음에는 같은
모노레포 안의 패키지를 빌드 시점에 정적으로 등록한다. 써드파티 동적 로딩은 확장이 다섯을 넘을 때 생각한다.

## 2. 어디까지 만드는가

세 단으로 나눈다.

**1단 (E0~E3, 이번 로드맵의 약속).** 옛 에디터가 하던 일을 전부 하고, 거기에 씬과 실행이 더해진다.

- 프로젝트를 열고 만든다 (템플릿: 빈 프로젝트, 플래피버드 예제)
- 스크립트(Lua, Ruby)를 쓰고 저장하면 실행 중인 게임이 다시 뜬다
- 실행 버튼으로 게임을 띄우고 출력을 콘솔에서 보며, 오류 줄을 누르면 그 자리로 간다
- 씬에 오브젝트를 놓고 속성을 고치고 저장하면 게임이 그 씬을 연다
- 타일맵 확장이 옛 기능(타일셋 팔레트, 4레이어 이상, 펜과 사각형과 채우기, 되돌리기, 맵 v2 열기와 저장)을 돌려주고, 타일맵이 씬의 오브젝트가 된다
- 다크와 라이트 테마, 도킹 레이아웃 저장
- macOS와 브라우저 모드에서 검증, Windows는 E1부터

**2단 (E4~E6).** 내장 플레이(게임 뷰 안에서 실행), RPG 확장(이벤트와 커맨드와 데이터베이스), 배포(설치 파일, 엔진 동봉, Linux).

**하지 않는다.** 에디터 전용 언어, 3D, 협업과 클라우드, 엔진 렌더링의 재구현 (index.md 6절). 비주얼 스크립팅은 에디터를 끝낸 뒤 검토한다 ([next-goals.md](next-goals.md) 3절).

## 3. 화면 구성

Unity와 VS Code에서 익숙한 배치를 따른다. 낯선 배치를 만들 이유가 없다.

```
+--------------------------------------------------------------------------------+
| 파일  편집  씬  실행  도구  창  도움말                                            |
+--------------------------------------------------------------------------------+
| [> 실행] [# 정지] [~ 리로드] | [선택] [이동] [확장 도구...] | 언어: Lua v | 씬: main v |
+----------------+-----------------------------------------------+---------------+
| 계층            | 탭: [씬 main] [player.lua] [게임 뷰]             | 인스펙터       |
|  v main        |                                               |  이름          |
|    bg  sprite  |     씬 뷰 (PIXI 8)                              |  위치, 크기,   |
|    map tilemap |     격자, 스냅, 선택 상자, 끌기, 줌,             |  회전, 투명도  |
|    player      |     카메라(논리 해상도) 사각형                   |  타입별 속성   |
|                |                                               |  스크립트 목록 |
+----------------+                                               +---------------+
| 프로젝트        |                                               | 확장 패널      |
|  > scripts/    |                                               |  타일 팔레트   |
|  > resources/  |                                               |  레이어        |
|    game.json   |                                               |               |
+----------------+-----------------------------------------------+---------------+
| 콘솔  [엔진 출력] [문제]                                   실행 중 (PID 1234)  |
+--------------------------------------------------------------------------------+
| 상태 바: ~/mygame | Lua | 씬 main | 저장 안 됨 2 | 브리지 연결됨 | 다크         |
+--------------------------------------------------------------------------------+
```

### 패널

| 패널 | 내용 | 코어인가 |
|---|---|---|
| 계층 | 열린 씬의 오브젝트 트리. 끌어서 순서(그리기 순서)를 바꾼다. 타입 아이콘은 확장이 준다 | 코어 |
| 프로젝트 | 프로젝트 폴더의 파일 트리. 더블클릭으로 문서를 연다(스크립트는 편집기, 씬은 씬 뷰, 이미지와 오디오는 미리보기). 새 파일과 이름 바꾸기와 삭제. 외부 변경은 감시로 반영 | 코어 |
| 문서 탭 | 씬 뷰, 스크립트, 게임 뷰(E4), 확장이 여는 문서. 저장 안 된 탭은 점 표시 | 코어 |
| 인스펙터 | 선택된 오브젝트나 자산의 속성. 공통 속성은 코어, 타입별 속성은 그 타입을 등록한 쪽이 React 컴포넌트로 준다 | 코어 + 확장 |
| 콘솔 | 엔진 stdout과 stderr, 브리지와 실행기 로그. `파일:줄:` 꼴은 링크. "문제" 탭은 저장 전 검증 결과(씬의 중복 id, 없는 경로) | 코어 |
| 확장 패널 | 확장이 `registerPanel`로 더한다. 타일 팔레트와 레이어가 첫 예 | 확장 |

### 레이아웃

- dockview로 끌어 옮기고 붙이고 띄운다. 레이아웃은 프로젝트의 `.initial-editor/layout.json`에 저장된다.
- 프리셋 셋. **씬**(위 그림), **스크립트**(편집기와 콘솔이 넓고 계층과 인스펙터는 접힘), **타일맵**(팔레트와 레이어가 크고 씬 뷰가 넓음). "창" 메뉴에서 고르고 초기화할 수 있다.
- 창은 하나다. 대화상자(새 프로젝트, 새 씬, 설정)는 앱 안의 모달이고, 폴더와 파일 선택만 OS 대화상자를 쓴다.

## 4. 문서 모델

에디터가 여는 것은 전부 **문서**이고, 문서는 저장과 되돌리기의 단위다.

| 문서 | 파일 | 되돌리기 | 저장 |
|---|---|---|---|
| 씬 | `resources/scenes/<이름>.json` | 씬당 스택 하나. 타일맵 확장의 타일 칠하기도 **같은 스택**에 들어간다 (두 개의 되돌리기는 혼란스럽다는 엔진 12 문서의 결정) | Ctrl+S. 타일맵 오브젝트가 참조하는 맵 파일도 함께 |
| 스크립트 | `scripts/lua/**`, `scripts/ruby/**` | Monaco 자체 | Ctrl+S, 저장 뒤 핫 리로드(설정으로 끌 수 있다) |
| 자산 | 이미지, 오디오, 폰트, `game.json` | 없음(읽기와 미리보기, `game.json`은 폼) | 폼이 곧 저장 |

문서 모델과 명령(`Command` 객체, `execute`와 `undo`)은 `packages/core`에 있어 DOM 없이 테스트된다.

## 5. 기능 목록과 단축키

| 메뉴 | 항목 | 단축키 |
|---|---|---|
| 파일 | 새 프로젝트, 프로젝트 열기, 최근 프로젝트, 저장, 모두 저장, 프로젝트 닫기 | Ctrl+N(새 씬은 씬 메뉴), Ctrl+O, Ctrl+S, Ctrl+Shift+S |
| 편집 | 되돌리기, 다시 실행, 잘라내기, 복사, 붙여넣기, 복제, 삭제, 찾기(스크립트) | Ctrl+Z, Ctrl+Shift+Z, Ctrl+X, Ctrl+C, Ctrl+V, Ctrl+D, Delete, Ctrl+F |
| 씬 | 새 씬, 오브젝트 추가(코어 타입과 확장 타입 목록), 시작 씬으로 지정, 격자 표시, 스냅 | Ctrl+Shift+N, Ctrl+Shift+A |
| 실행 | 실행, 정지, 현재 씬부터 실행, 리로드(핫 리로드 push), 언어 선택(Lua, Ruby), 엔진 경로 | F5, Shift+F5, Ctrl+F5, Ctrl+Shift+R |
| 도구 | 설정(테마, 편집기 폰트, 저장 시 리로드, 엔진 경로), 확장이 더하는 항목(타일맵: 맵 가져오기와 내보내기) | |
| 창 | 패널 표시 토글, 레이아웃 프리셋, 레이아웃 초기화 | |
| 도움말 | 엔진 API 대응표(엔진 README), 계획 문서, 버전 | |

macOS에서는 Ctrl이 Cmd다. 단축키는 코어의 `registerCommand`에 적고, 메뉴와 툴바와 키는 같은 커맨드를 가리킨다
(옛 에디터에서 메뉴 단축키가 전부 빈 문자열에 묶였던 버그의 재발 방지).

## 6. 테마

### 원칙

1. **색은 토큰(CSS 변수)으로만 쓴다.** 컴포넌트와 확장은 `var(--...)`만 쓰고 색 리터럴을 쓰지 않는다. CI에 색 리터럴 검사를 둔다 (토큰 파일 밖의 `#`, `rgb(`를 grep).
2. 테마는 `<html data-theme="dark|light">` 하나로 바뀐다. 토큰 파일 한 장(`packages/app/src/theme/tokens.css`)에 다크와 라이트가 나란히 있다.
3. 기본은 **OS 설정을 따른다.** `prefers-color-scheme`과 Tauri 창의 테마 이벤트를 듣는다. 설정에서 고정할 수 있다.
4. 새 테마(고대비 등)는 토큰 값 한 벌을 더하는 것으로 끝나야 한다.

### 토큰 (첫 벌)

| 묶음 | 토큰 |
|---|---|
| 바탕 | `--bg-base`, `--bg-panel`, `--bg-elevated`, `--bg-input`, `--bg-hover`, `--bg-selection` |
| 글자 | `--fg`, `--fg-muted`, `--fg-disabled`, `--fg-on-accent` |
| 강조와 상태 | `--accent`, `--danger`, `--warning`, `--success`, `--border`, `--focus-ring` |
| 씬 뷰 | `--scene-bg`, `--scene-grid`, `--scene-grid-major`, `--scene-selection`, `--scene-camera` |
| 글꼴과 형태 | `--font-ui`, `--font-mono`, `--radius`, `--space-1` ~ `--space-4` |

### 토큰이 닿아야 하는 곳

- **Monaco**: 테마가 바뀔 때 `defineTheme`으로 토큰 값을 매핑한 테마를 다시 정의하고 적용한다.
- **dockview**: 자체 테마 클래스를 쓰지 않고 토큰으로 스타일을 덮는다.
- **PIXI 씬 뷰**: 배경과 격자와 선택 상자 색을 `getComputedStyle`로 읽어 테마가 바뀔 때 다시 그린다.
- **확장 패널**: 토큰만 쓴다. 타일 팔레트의 선택 테두리도 `--accent`다.

옛 `ThemeManager`와 `conf/theme.json`(토큰 7개)은 이 방식으로 대체된다. 옛 토큰 이름이 `--dark-*`로 시작해
라이트 테마에서도 "dark"였던 것이 교훈이다. 새 이름은 역할로만 짓는다.

## 7. 알림과 상태

- 결과는 콘솔에, 짧은 알림은 토스트에(옛 `useToast` 정책 유지), 진행 중 상태는 상태 바에.
- 위험한 것(덮어쓰기, 삭제, 외부에서 바뀐 파일 위에 저장)은 앱 안의 모달로 한 번 묻는다.
- 실행 중인 게임이 있으면 상태 바에 PID와 경과 시간을 보이고, 정지 버튼이 활성이다.
