# RPG Maker 2000 타일맵 확장 (ext-rm2k)

2026-10-24 저자 요청: "RPG Maker 2K 타일맵을 구현하는 플러그인을 만드세요. 오토타일이 가능해야 합니다."

## 1. 목표와 경계

- RPG Maker 2000의 ChipSet(480x256)을 그대로 가져와 같은 팔레트(하층, 상층)로 칠하고, 땅과 물의 오토타일이 RPG Maker 2000과
  같은 모양으로 맞춰지며, 물과 애니메이션 타일이 게임에서 움직인다.
- 엔진은 오토타일을 모른다 (엔진 roadmap-v2.md 13단계의 "굽기"). 에디터가 ChipSet의 8x8 조각을 모아 모양마다 16x16 타일 한 장씩
  아틀라스로 굽고, 맵에는 그 gid를 적는다. 엔진에 더한 것은 장르와 상관없는 타일 애니메이션 하나다 (엔진 02-tilemap.md의
  타일 애니메이션, `Tilemap.Update`, 범위 `count`).
- RPG 전용 지식(ChipSet의 배치, 47 모양 표, 물의 모서리 규칙)은 에디터의 확장 `packages/ext-rm2k`에만 있다. 타일맵 확장
  (`ext-tilemap`)에는 장르와 상관없는 자리만 연다: 타일셋 종류(팔레트 쪽, 모양 맞추기 규칙, 새 맵에서의 변환).

## 2. ChipSet 배치

근거는 EasyRPG Player의 `src/tilemap_layer.cpp`, `src/map_data.h`, `src/game_map.cpp`와 EasyRPG Editor의 `src/core.cpp`,
`src/ui/map/map_scene.cpp`, `src/ui/common/palette_scene.cpp`, liblcf의 `chipset.h`다. 로컬 RTP의 Exterior.png로 눈으로도 맞췄다.

| 구역 | 픽셀 사각형 | 내용 |
|---|---|---|
| 물 A1 물가 | (0, 0, 48, 64) | 세로 줄 셋이 프레임. 줄마다 바깥 모서리, 세로 물가, 가로 물가, 안쪽 모서리 |
| 물 A2 물가 | (48, 0, 48, 64) | 같은 구조. 깊은 물은 A1의 물가를 쓴다 |
| 물 몸통 | (0, 64, 48, 64) | 세로 줄 셋이 프레임. 얕은 물, 깊은 모서리가 든 얕은 물, 얕은 모서리가 든 깊은 물, 깊은 물 |
| 애니메이션 타일 C1..C3 | (48, 64, 48, 64) | 타일마다 세로로 프레임 넷 |
| D1..D4 | (0, 128), (48, 128), (0, 192), (48, 192) | 48x64 덩어리 |
| D5..D12 | (96, 0)부터 (144, 192)까지 | 48x64 덩어리 여덟 |
| E | (192, 0, 96, 256), (288, 0, 96, 128) | 6열 줄 안에서 행 우선 |
| F | (288, 128, 96, 128), (384, 0, 96, 256) | 6열 줄 안에서 행 우선 |

투명색: 팔레트 PNG는 0번 색 (tRNS와 상관없이), 그 밖에는 이미지의 알파, 알파가 없으면 (288, 128)의 색.

## 3. 모양

- 모양 번호는 땅과 물이 같은 47가지다. 가장자리는 같지 않은 동서남북 이웃, 모서리는 동서남북 둘이 같은데 그 사이 대각선만 다른
  이웃이다. 닫힌 식은 `shapes.ts`의 `blobVariant`.
- 땅의 표(조각마다 D 덩어리의 어느 타일)와 물의 표(조각마다 물가 줄)는 EasyRPG Player의 `BlockD_Subtiles_IDS`,
  `BlockA_Subtiles_IDS`를 옮긴 것이다. 따로 옮긴 두 표가 이웃 256가지 모두에서 원리로 정한 조각 분류와 같은지
  `shapes.test.ts`가 본다.
- 물의 모서리 비트(깊은 물과 얕은 물): Player와 Editor의 규칙이 맵 가장자리와 대각선에서 다르다. 에디터이므로 EasyRPG Editor의
  규칙을 따른다 (얕은 물: 동서남북 둘이 깊은 물이고 대각선이 물, 깊은 물: 동서남북 둘과 대각선이 모두 얕은 물). 비트가 선 조각은
  물가보다 앞선다.
- 같은 지형: 땅은 같은 D 번호만, 물가는 물 A1, A2, 깊은 물, 애니메이션 타일 모두. 맵 밖은 같은 지형이다.

## 4. 아틀라스 (판 1)

48열 79줄 (768x1264). 번호(타일셋 안의 번호):

| 번호 | 내용 |
|---|---|
| 0..143 | E0..E143 |
| 144..287 | F0..F143 |
| 288..863 | D1..D12. 종류마다 48칸: 모양 0..46, 47은 견본(팔레트 그림) |
| 864..875 | 애니메이션 타일. 프레임 f의 C(n+1)은 864 + f*3 + n |
| 912..3791 | 물. 프레임 f, 종류 k, 물 칸 t는 912 + f*960 + k*306 + t |

물 칸 t는 그림이 다른 (모양, 모서리 비트) 306가지다 (모서리 비트가 0인 47개가 먼저라 t = 모양). 애니메이션 타일과 물 전부가
타일셋 `animations`의 범위 하나씩이다. 배치를 바꾸면 이미 칠한 맵의 gid가 다른 그림을 가리키므로 `ATLAS_VERSION`을 올린다.

## 5. 에디터

- `ext-tilemap`: `TilemapApi.registerTilesetKind`, `tilesetKind`, `autotileRules`. 모양 맞추기는 `model/autotileRules.ts`의
  `applyAutotile`(칠한 칸과 이웃 8칸, 순수 함수). 채우기는 `floodFillArea`의 `regionOf`로 같은 지형을 한 영역으로 본다.
- 맵 뷰: 타일셋의 `animations`를 엔진과 같은 규칙(`tileAnimation.ts`의 `animatedGid`)으로 재생한다. 보기 설정 `animate`(맵 >
  타일 애니메이션 재생)를 끄면 시계 0이다.
- 앱: 맵 도구의 칠하기 한 곳(`MapToolController.apply`)이 타일 레이어의 바뀜을 규칙에 넣는다. 이웃의 모양 변경도 같은 되돌리기
  단계다. 팔레트는 종류가 준 쪽을 탭으로 보이고 칸마다 아틀라스의 그림을 그린다. 새 맵 대화상자는 그림을 받는 종류가 있으면
  형식과 종류의 선택지를 보이고, 만들 때 종류의 `createTileset`이 아틀라스를 쓴다.
- `ext-rm2k`: 타일셋 종류 등록, 열린 맵의 원본 ChipSet이 바뀌면 다시 굽기, 맵을 열 때 아틀라스가 없으면 굽기.
- PNG 읽기와 쓰기는 `core/png.ts` (CompressionStream, 팔레트 번호까지).

## 6. 검사

- 단위: `packages/ext-rm2k/src/**/*.test.ts` (표, 아틀라스, 굽기, 규칙, 확장), `ext-tilemap`의 `autotileRules.test.ts`와
  채우기의 영역 열쇠, `core/png.test.ts`, 앱의 팔레트 쪽 도우미.
- 엔진 교차 검사 `yarn test:engine-rm2k`: 검사용 ChipSet(조각마다 제 자리를 색으로 든 이미지)을 굽고 규칙으로 칠한 맵을 진짜
  엔진으로 시계 넷에서 찍어, 칸마다 네 조각이 그 시계의 프레임으로 옮긴 아틀라스 칸과 같은지 본다. 물과 애니메이션 타일 칸이
  시계마다 바뀌는지, 저장한 맵이 엔진의 `tools/mapfile.py check`를 지나는지도 본다. 타일 애니메이션 전 엔진이면 SKIP.
- e2e `tests/e2e/rm2k-tilemap.spec.ts`: 새 맵 대화상자의 형식과 선택지, 맵 파일과 아틀라스, 팔레트 두 쪽, 사각형으로 칠한 땅의
  모양과 되돌리기 한 번, 물과 깊은 물, 물 영역 채우기.
