# 완성도 계획: 끝까지 만든 에디터

> 작성일: 2026-10-24. 에디터 로드맵(`index.md`)의 E0부터 G까지가 끝난 뒤의 계획이다.
> 앞의 단계들은 기능이 있고 자동 검사를 통과한다는 뜻의 완료였다. 이 문서의 완료는 사람이 써서 손볼 데가 없다는 뜻이다.

## 1. 저자 판정

2026-10-24 저자의 말이다.

> 에이전트를 쓰지 않은 시절에는 그래도 사용한 문장이나 용어에 인간적인 느낌이 있었습니다. 하지만 에디터를 에이전트로 개선 작업을 한 이후부터 전체적인 느낌이 쓰레기가 되어가고 있습니다. 사용성, 그리고 UI의 크기나 하나의 기능에도 디테일하지 않아보입니다. 에디터는 게임을 만들어내기 위함인데, 개발부터, 스프라이트, 셰이더, 각종 편집에 이르기까지. 그리고 배포까지. 뭐 하나 쉽게 디테일하게 완성되는게 없어보입니다.

판정이 맞다. 아래는 같은 날 기본 창(1400x900)과 최소 창(960x600)에서 처음 쓰는 사람의 순서대로 화면을 찍어 확인한 것이다. 사진은 [docs/design/before-2026-10-24/](../design/before-2026-10-24/)에 있다.

## 3. 왜 이렇게 되었나

1. **완료 기준이 자동 검사뿐이었다.** E0부터 G까지 열세 단계가 2026-09-26부터 10-05까지 열흘 사이에 ✅가 되었다. 기준은 테스트 수와 자체 시험이었고, 사람이 그 화면을 쓸 때 어떤지는 기준에 없었다.
2. **넓이를 먼저 늘렸다.** 화면 하나를 끝내기 전에 다음 패널과 기능을 얹었다. 그래서 어느 화면도 끝나지 않았다.
3. **화면이 내부 구조를 그대로 보여 준다.** 패널이 코드의 모듈과 하나씩 대응하고 (확장 패널, 맵 오브젝트, 팔레트, 레이어, 이벤트), 파일 형식의 키(`gid`, `props`, `events[N]`)와 구현 이름(스키마, 명세, 씬 로더, 백엔드, `memory://`)이 사용자에게 나간다. 쓰는 방법은 화면 안의 문단으로 설명한다.
4. **문구를 규칙표로 기계적으로 바꿨다.** `docs/design/ui-terms.md`의 용어표는 저자가 쓰던 말(편집기, 가로, 세로, 폭, 글꼴, 그림, 눈, 소재)을 "쓰지 않는 말"로 두었고, 2178개 문자열을 한 번에 다시 썼다 (커밋 `75132b9`). 그 결과 `band`, `gid` 같은 말은 남고 사람이 쓰던 말은 빠졌다.

## 4. 목표

> **처음 쓰는 사람이 설명서를 펴지 않고 플래피버드를 만들어 친구에게 보낼 수 있다. 그 사이에 지나는 어느 화면도 손볼 데가 없다.**

그다음은 항구 마을 같은 작은 RPG를 같은 수준으로 만드는 것이고, 그다음이 효과와 셰이더다.

## 5. 일하는 방식

이 절이 계획에서 가장 중요하다. 같은 방식으로 일하면 같은 결과가 나온다.

### 5.1 화면 완성 기준

화면(또는 대화상자, 패널) 하나는 아래를 모두 만족할 때 끝난다. 테스트 통과는 필요 조건일 뿐이다.

1. 기본 창(1400x900)과 최소 창(960x600), 다크와 라이트에서 잘리는 글자와 겹치는 요소가 없다.
2. 빈 상태, 불러오는 중, 오류, 내용이 많은 상태가 모두 설계되어 있다. 빈 패널은 띄우지 않는다.
3. 개발자용 내용이 없다: 파일 형식의 키, 구현 이름, 파일 경로로 하는 설명, 쓰는 방법을 설명하는 문단.
4. 6절의 부품과 크기 토큰만 쓴다. 같은 동작은 어디서나 같은 모양이다.
5. 키보드로 다 할 수 있고 포커스가 보인다.
6. 같은 종류의 첫 화면은 저자가 보고 승인한 뒤에 나머지로 넓힌다.

### 5.2 화면 검수판

`yarn review`가 모든 화면과 상태를 두 테마, 두 창 크기로 찍어 HTML 한 장으로 묶는다 (Playwright, 웹판의 메모리 모드와 브라우저 폴더 모드). PR마다 바뀐 화면의 전후 사진을 붙인다. 에이전트는 사진을 직접 보고 5.1의 기준으로 검사한 뒤에 PR을 올린다.

### 5.3 깊이 먼저

진행 중인 단계가 끝나기 전에는 새 패널이나 새 기능을 더하지 않는다. 한 PR은 화면 하나를 끝낸다.

### 5.4 문구는 화면을 보면서 고친다

문자열을 일괄로 바꾸지 않는다. 화면 하나를 고칠 때 그 화면의 말을 그 자리에서 다시 쓴다. 기준은 7절이다.

## 6. 디자인 기반

### 6.1 크기 토큰

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| 글자 | 11px 작게, 12px 보조, 13px 기본, 15px 제목, 20px 큰 제목 | 기본을 12px에서 13px로 올린다. 한국어는 12px에서 받침이 뭉친다 |
| 줄 높이 | 1.45 (한국어 기준) | 본문과 목록 |
| 컨트롤 높이 | 28px 기본, 24px 작게 (도구 모음과 목록 안), 32px 크게 (대화상자의 주 버튼) | 단추, 입력 칸, 선택 |
| 목록 줄 | 26px | 계층, 프로젝트, 레이어, 이벤트, 커맨드 |
| 간격 | 4px 단위 (4, 8, 12, 16, 24, 32) | 여백과 간격 전부 |
| 모서리 | 4px 컨트롤, 6px 카드와 대화상자 | |
| 아이콘 | 16px, 도구 모음의 큰 단추는 20px | |
| 패널 머리 | 32px | |

`font-size`, `padding`, `margin`, `gap`, `height`에 토큰이 아닌 px를 쓰면 검사가 실패한다 (색 검사 `check-color-literals.mjs`와 같은 방식).

### 6.2 부품

`packages/ui`에 둔다. 패널은 이 부품만 쓰고 `<button>`, `<input>`, `<select>`를 직접 쓰지 않는다 (검사로 막는다).

- 단추: Button (기본, 주, 위험, 투명), IconButton (아이콘만, 툴팁 필수), ToggleButton, SegmentedControl
- 입력: TextField, NumberField (끌어서 값 바꾸기, 단위 표시), Vector2Field (x, y 한 줄), Select, Checkbox, Switch, ColorField, AssetField (썸네일로 고르기, 끌어다 놓기)
- 구조: PanelHeader, Toolbar, ListRow와 Tree, Tabs, Section (접기), Card
- 상태: EmptyState (그림, 한 줄 설명, 할 일 단추 하나), Badge, Progress, Toast
- 겹 화면: Dialog, Popover, ContextMenu, Tooltip

### 6.3 아이콘

한 벌을 쓴다. Lucide(ISC 라이선스, 선 굵기 1.5)를 쓰고, 게임 도구에만 있는 것(타일 펜, 통행, 오토타일, 이벤트)은 같은 선 굵기로 직접 그린다. 같은 동작은 같은 아이콘이다: 보이기는 눈, 잠그기는 자물쇠, 지우기는 휴지통, 순서는 손잡이를 잡고 끌기.

### 6.4 견본 화면

`?ui=gallery`가 모든 부품과 상태를 한 화면에 보여 준다. 저자 검수의 첫 대상이다.

## 7. 문구

### 7.1 원칙

저자가 혼자 쓰던 문장(옛 에디터의 메뉴와 대화상자, 엔진 README)에서 가져온 원칙이다.

1. 문장은 합니다체로 짧게 쓴다. 이유가 필요하면 "~기 때문입니다"로 한 번만 댄다.
2. 사용자가 만드는 것은 게임이다. 프로젝트는 폴더를 가리킬 때만 쓴다.
3. 이름표와 메뉴는 명사로 쓴다 ("플레이 테스트", "게임 폴더 열기").
4. 오류는 무엇이 잘못되었는지 말하고, 확인할 것을 말한다. "이미지를 불러오지 못했습니다. 파일이 있는지 확인하십시오."
5. 화면 안에 사용법 문단을 쓰지 않는다. 필요하면 툴팁 한 줄이나 가이드 링크로 둔다.
6. 엔진이나 에디터의 한계를 설명하지 않는다. 고치거나, 그 기능을 감춘다.

### 7.2 화면에 쓰지 않는 것

- 파일 형식의 키: `gid`, `firstGid`, `props`, `events[N]`, `band`, JSON 경로
- 구현 이름: 스키마, 명세, 씬 로더, 백엔드, 분석기 이름, `memory://`, 확장 id(`tilemap`, `rpg`)
- 파일 경로로 하는 설명: "resources/schema/map-objects.json을 만들면..."
- "활성 X 탭 없음" 같은 상태 문장: 그 상태에서는 패널을 감추거나 할 일을 보여 준다

### 7.3 용어표 개정

`docs/design/ui-terms.md`의 금지어 가운데 저자가 쓰던 말은 되살린다. 정할 것은 9절에 모았다.

| 대상 | 지금 | 제안 | 근거 |
|---|---|---|---|
| 테스트 실행 | 실행 | 플레이 테스트 (메뉴), 실행 (단추) | 옛 메뉴 "플레이 테스트" |
| 게임 만들기와 열기 | 새 프로젝트, 프로젝트 열기 | 새 게임, 게임 열기 | 옛 도구 모음 "게임 만들기", "게임 열기" |
| 게임 설정 | (game.json 직접 편집) | 게임 속성 | 옛 대화상자 "게임 속성" |
| 크기 | 너비, 높이 (가로, 세로 금지) | 가로, 세로 | 옛 대화상자 "가로 크기", "세로 크기" |
| 레이어 보이기 | "보이기", "숨김" 글자 | 눈 아이콘 (툴팁 "보이기") | 옛 레이어 목록 |
| 설정 | 설정 | 환경 설정 | 옛 메뉴 "환경 설정" |

## 8. 단계

마일스톤 셋으로 나눈다. 마일스톤 1이 4절의 목표 문장이다.

### 마일스톤 1: 플래피버드를 만들어 보낸다

#### Q0. 디자인 기반

- 6절 전부: 크기 토큰, 부품, 아이콘, 견본 화면, 크기 검사와 부품 검사
- `yarn review` (5.2절)
- 완료 기준: 견본 화면을 저자가 승인한다

#### Q1. 처음 10분

- **시작 창.** 게임이 열려 있지 않으면 작업 화면 대신 시작 창을 띄운다: 새 게임, 게임 열기, 최근 게임 (마지막 화면의 작은 그림), 샘플
- **새 게임.** 템플릿 카드 (그림과 한 줄 설명), 게임 이름, 위치, 화면 크기 (세로 모바일, 가로 HD, 도트 320x240 ×3, 직접 입력), 스크립트 언어. 만들면 시작 씬이 열린다
- **게임 속성.** 게임 이름, 화면 크기와 배율, 아이콘, 시작 씬, 스크립트 언어. `game.json`을 직접 고치지 않아도 된다. 도구 모음의 언어와 씬 선택은 여기로 옮긴다
- **작업 화면.** 씬, 맵, 스크립트 셋. 그 작업에 쓰지 않는 패널은 닫혀 있다. 확장 패널은 없앤다
- **콘솔.** 게임이 찍은 것과 오류만 보인다. 에디터의 진행 기록은 도움말 메뉴의 에디터 로그로 옮긴다
- 완료 기준: 처음 보는 사람이 템플릿으로 게임을 만들어 실행할 때까지 클릭이 셋 이하다. 시작 창과 새 게임을 저자가 승인한다

#### Q2. 씬 편집

- **씬 뷰.** 오브젝트마다 "에디터에서 숨기기" (게임에는 영향 없음)를 두어 상태별 글자가 겹치지 않게 한다. 선택 핸들 (이동, 크기, 회전), 정렬 안내선, 카메라 영역, 트랙패드와 휠의 확대와 이동, 프로젝트에서 이미지를 끌어다 놓으면 스프라이트
- **계층.** 부모와 자식, 접기, 여러 개 선택, 찾기
- **인스펙터.** 부품으로 다시 짠다. 위치는 한 줄 (x, y), 크기와 배율과 회전, 이미지는 썸네일로 고르기, 애니메이션 고르기, 스크립트는 접히는 카드 (매개변수 포함), 글자는 글꼴과 색과 크기
- **실행 중.** 게임 탭이 열려도 계층과 인스펙터는 씬을 계속 보여 준다
- 엔진 짝 (Initial2D, 아래 10절의 엔진 1): 글자 색과 크기, 색 입히기, 피벗, 뒤집기, 부모와 자식 좌표
- 완료 기준: 플래피버드 씬을 템플릿 없이 처음부터 만들 수 있고, 씬 뷰와 실행 화면이 같아 보인다

#### Q3. 스프라이트와 애니메이션

- **가져오기.** 운영체제에서 끌어다 놓기, 파일 메뉴의 가져오기. 가져온 이미지는 `resources/images/`로 들어간다
- **이미지 보기.** 확대, 픽셀 격자, 투명 부분의 바둑판 배경
- **시트 자르기.** 칸 크기나 행과 열 수, 여백, 간격. 자른 결과를 그 자리에서 보여 준다
- **애니메이션.** 이름 있는 클립 (`fly`, `fall` 같은), 프레임마다 시간, 반복 방식, 재생 미리보기, 피벗
- **저장 형식.** 이미지 옆의 시트 파일 하나 (`bird.sprite.json`). 엔진 짝이 읽는다
- 엔진 짝 (엔진 2): 시트 파일과 클립 재생
- 완료 기준: 새가 날갯짓 클립과 떨어지는 클립을 바꿔 가며 쓰는 플래피버드를 시트 파일과 인스펙터만으로 만든다

#### Q4. 게임 내보내기 (웹, macOS)

- **내보내기 대화상자.** 대상, 게임 이름, 아이콘, 버전, 저장할 곳. 끝나면 "폴더 열기"
- **웹.** 앱에 든 WASM 엔진과 게임 파일로 폴더 하나 (그대로 올리면 itch.io나 Cloudflare Pages에서 돈다)
- **macOS.** 앱 묶음 하나 (`.app`, 엔진과 게임 파일과 아이콘)
- **저장 데이터.** 최고 점수를 남기는 엔진 API (엔진 4)
- 엔진 짝 (엔진 3, 엔진 4): 실행 파일 위치 기준의 게임 폴더, 게임 이름과 아이콘, 저장 데이터
- 완료 기준: 에디터로 만든 플래피버드를 웹과 macOS로 내보내 다른 컴퓨터에서 실행하고, 최고 점수가 다시 켜도 남는다

### 마일스톤 2: 작은 RPG를 만든다

#### Q5. 맵과 이벤트

- 맵 작업 화면을 사이드바 하나로 정리한다: 맵 목록 (트리), 타일셋 (탭), 레이어 (눈 아이콘)
- 오토타일 칠하기, 통행 칠하기의 표시, 맵 속성 창
- 이벤트 목록과 커맨드 편집을 RPG 만들기 도구의 손맛으로 다시 짠다: 커맨드는 대화상자에서 고르고, 목록은 사람이 읽는 문장으로 보인다 ("문장: 어서 오세요")
- 완료 기준: 항구 마을의 이벤트 하나를 처음부터 만드는 동안 파일 경로나 JSON을 한 번도 보지 않는다

#### Q6. 소리, 글꼴, 데이터

- 소리 미리 듣기 (재생, 정지, 반복, 파형), 소리를 고르는 곳마다 재생 단추
- 글꼴 굽기 대화상자 (TTF에서 비트맵 글꼴, 지금은 `tools/generate_bmfont.py` 명령줄), 글꼴 미리보기
- 표 편집기 (아이템 같은 JSON 배열)
- 완료 기준: 아이템 셋과 효과음 넷을 에디터 안에서만 만들고 고른다

#### Q7. 디버깅

- 실행 중인 게임의 오브젝트와 값을 인스펙터에서 본다
- 일시 정지와 한 프레임씩 진행
- Lua 중단점과 단계 실행 (엔진 5). Ruby는 그 뒤
- 완료 기준: 점수가 오르지 않는 버그를 중단점 하나로 찾는다

### 마일스톤 3: 보기 좋은 게임

#### Q8. 효과

- 셰이더 없이 되는 것부터 (엔진 1의 나머지): 혼합 모드 (더하기, 곱하기), 화면 효과 (페이드, 번쩍임, 흔들기), 도형, 입자. 에디터는 인스펙터와 입자 편집기 (미리보기)
- 완료 기준: 플래피버드의 충돌에 번쩍임과 흔들기, 점수에 입자를 붙인다

#### Q9. 셰이더

- 지금 엔진은 SDL_Renderer로 그려 셰이더를 쓸 수 없다. 렌더러를 바꿔야 하므로 방식을 저자가 정한다 (9절)
- 정해지면: 스프라이트에 붙는 조각 셰이더와 화면 전체에 거는 셰이더, 에디터의 셰이더 편집 (문법 강조, 오류 줄, 게임 탭의 즉시 미리보기)

#### Q10. 안드로이드 내보내기

- 게임마다 앱 ID, 이름, 아이콘, 버전. 미리 빌드한 APK에 게임 파일을 넣는 방식 (NDK 없이), 서명
- 완료 기준: 에디터만으로 APK를 만들어 휴대폰에 설치한다

## 9. 정할 것

1. **용어 (7.3절).** 저자가 쓰던 말로 되살리는 여섯 가지를 그대로 받을지.
2. **셰이더의 렌더러 (Q9).** 선택지는 다음과 같다.

   | 방식 | 데스크톱 | 안드로이드 | 웹 | 비용 |
   |---|---|---|---|---|
   | 자체 렌더러, GLSL ES 3.0 한 가지 | OpenGL 3.3 (macOS는 4.1에서 멈춘 OpenGL) | OpenGL ES 3 | WebGL2 | TextureManager를 다시 짠다. 사용자 셰이더를 변환 없이 쓴다 |
   | sokol_gfx | Metal, OpenGL, D3D11 | OpenGL ES 3 | WebGL2 | 셰이더를 빌드 때 변환한다 (sokol-shdc). 에디터에 변환기를 싣는다 |
   | SDL3의 SDL_GPU | Metal, Vulkan, D3D12 | Vulkan | WebGL 백엔드가 없다 | 웹판이 막힌다 |

   권고는 자체 렌더러다. 사용자가 쓰는 셰이더 언어가 하나이고, 웹과 안드로이드에서 그대로 돌며, 변환기를 에디터에 실을 필요가 없다. 대신 macOS는 더 이상 발전하지 않는 OpenGL 위에서 돈다.
3. **Windows용 게임 내보내기.** Windows 엔진(R5)은 하지 않기로 했었다. Windows 플레이어에게 보낼 일이 있으면 다시 정한다.
4. **첫 검수 대상.** Q0의 견본 화면과 Q1의 시작 창. 이 둘이 승인되기 전에는 다른 화면에 넓히지 않는다.
