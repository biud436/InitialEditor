# E3: 타일맵 확장

**권장 모델**: Claude Opus 5. 옛 코드의 로직을 정해진 확장 API로 옮기는 작업이며, 설계는 [04-extensions-and-tilemap.md](04-extensions-and-tilemap.md)에서 끝났다.
확장 API가 부족해 코어를 고쳐야 하는 지점이 나오면 그때 Fable 5로 승격한다.

> 목표: **옛 에디터로 하던 일을 전부 하고, 타일맵이 씬의 오브젝트가 된다. 맵을 열어서 저장해도 `events`를 잃지 않는다.**

## 선행 조건

- E2 완료 (오브젝트 타입 등록, 씬 문서의 되돌리기 스택, 인스펙터 자리).

## 작업 항목

### 마일스톤 1: 잃지 않기 (가장 먼저)

엔진 12 문서의 마일스톤 1이다. 지금 옛 에디터로 v2 맵을 열면 거부하고, v1으로 저장하면 `events`가 사라진다.

- [ ] `ext-tilemap/src/format/`: 옛 `MapFormat.ts`를 옮기고 v1과 v2를 모두 읽는다. 쓰기는 항상 v2
- [ ] 편집하지 않는 키(`events`, 통행 레이어, 레이어 이름, 그 밖의 모르는 키)를 그대로 되돌려 준다
- [ ] 픽스처: 엔진의 `sample_v2.json`과 `port_town.json` 왕복이 동등. 옛 `map_v1_contract.json` 테스트도 그대로 통과
- [ ] 빈 칸의 내부 표현을 `-1`로 바꾸고 파일의 gid 0과 변환한다. 첫 타일셋의 첫 타일이 살아난다

### 마일스톤 2: 모델 이전

- [ ] 타일맵 데이터(`number[]`, 레이어 수는 파일이 정한다), 펜과 사각형과 채우기(플러드 필)와 지우개 알고리즘을 `ext-tilemap/src/model/`로. DOM 없이 `node --test`
- [ ] `PaintTilesCommand`: 옛 `TilemapHistory.ts`의 델타 기록을 명령 객체로. 씬 문서의 스택에 들어간다
- [ ] 크기 바꾸기(겹치는 영역 유지)

### 마일스톤 3: 타일셋 자산과 팔레트

- [ ] 타일셋 자산 타입 등록: 이미지 + 타일 크기. 프로젝트 패널에서 미리보기
- [ ] 팔레트 패널: 타일셋 여러 장을 세로로 이어 보이고, 클릭과 끌기로 선택 영역(여러 칸)을 잡는다. 선택 테두리는 `--accent`
- [ ] 타일셋 순서는 맵 파일의 `tilesets` 순서다 (옛 에디터에서 로드 완료 순서로 흔들리던 버그의 재발 방지)

### 마일스톤 4: 도구와 레이어

- [ ] 씬 뷰 도구 등록: 펜, 사각형, 채우기, 지우개, 스포이드. 타일맵 오브젝트가 선택됐을 때만 활성
- [ ] 씬 뷰 위에 커서 미리보기(선택한 타일 묶음이 마우스를 따라온다)
- [ ] 레이어 패널: 목록, 가시성, 현재 레이어, 이름, 추가와 삭제와 순서, `groundLayers` 경계 표시
- [ ] 큰 맵(256x64, 알데바란)에서 칠하기가 끊기지 않는다. 필요하면 레이어별 렌더 텍스처 캐시

### 마일스톤 5: 타일맵 오브젝트 타입과 런타임 짝

- [ ] `registerObjectType("tilemap")`: props는 `map`(파일), `groundLayers`. 인스펙터에서 맵 파일 고르기와 새 맵 만들기(이름, 크기, 타일 크기, 타일셋)
- [ ] 씬 뷰 렌더링: 레이어를 순서대로, `groundLayers` 위는 반투명 토글
- [ ] 엔진 저장소에 `scripts/lua/scene_types/tilemap.lua`와 Ruby 판. `Tilemap.load`로 열고 `groundLayers`를 적용한다
- [ ] 저장 시 씬 파일과 맵 파일을 함께 쓴다. 맵 파일만 바뀌어도 씬 문서가 dirty다

### 마일스톤 6: 통행 편집

- [ ] 통행 레이어 편집 모드(도구 하나): 막힘 칠하기와 지우기, 반투명 오버레이
- [ ] 엔진의 충돌 레이어 형식을 그대로 쓰고, 엔진 씬 테스트로 막힘이 맞는지 확인

### 마일스톤 7: 마무리

- [ ] 옛 v1 형식 내보내기를 도구 메뉴에 (호환용)
- [ ] `legacy/` 삭제. 옛 에디터가 하던 일의 목록([04-extensions-and-tilemap.md](04-extensions-and-tilemap.md) 이전표)을 하나씩 새 에디터에서 확인한 뒤
- [ ] 오토타일은 `AutoTile.ts`를 `model/autotile.ts`로 옮겨 두기만 한다 (도구는 엔진 13단계와 함께)

## 완료 기준

- [ ] `port_town.json`을 열어 타일 한 칸을 칠하고 저장해도 엔진의 항구 마을 인수 시나리오가 **무변경으로 통과**한다 (짐 상자 이벤트가 그대로 돈다)
- [ ] 새 맵을 칠해 씬의 타일맵 오브젝트로 저장하면 엔진이 같은 화면을 그린다 (골든)
- [ ] 옛 기능 이전표의 항목이 전부 새 에디터에서 된다
- [ ] 통행 편집 결과가 엔진의 막힘과 일치한다 (씬 테스트)
- [ ] `legacy/`가 없다
- [ ] 두 저장소의 README에 사용법이 있다

## 의존 관계

- 선행: E2
- 후행: E5(이벤트 오브젝트가 타일맵 격자에 놓인다), 오토타일

## 위험

- **옛 `tilemap.ts`에 숨은 규칙.** 1,052줄 갓 클래스에 렌더링과 데이터와 입력이 섞여 있어 옮기다 놓치는 규칙이 있을 수 있다. 대응: 마일스톤 2에서 데이터 로직만 옮기고, 옛 에디터와 같은 입력에 같은 배열이 나오는지 비교 테스트를 둔다.
- **성능.** PIXI 8에서 타일을 스프라이트 하나씩 그리면 큰 맵이 느리다. 대응: 마일스톤 4의 기준을 알데바란 맵으로 잰다. 필요하면 레이어 렌더 텍스처.
