# UI 용어와 문구 규칙

에디터 화면, 알림, 콘솔, 오류에 쓰는 말을 정한다. 같은 대상은 어디서나 같은 말로 부르고, 비유 대신 코드가 부르는 대상의 이름을 쓴다.

기준 예: `이 타입은 칸이 없다` → `추가 속성 없음`

## 1. 용어표

### 공통

| 대상 | 쓰는 말 | 쓰지 않는 말 |
|---|---|---|
| InitialEditor와 코드 편집 화면 | 에디터 | 편집기 |
| 제품, 엔진, 파일 형식의 version | 버전 | 판 |
| 파일이나 데이터를 가져오는 진행 상태 | 불러오는 중 | 읽는 중 |
| 값을 선언의 기본값으로 되돌리는 버튼 | 기본값 복원 | 기본값으로 |
| 프로젝트의 씬 로더를 내장 파일로 덮어쓰는 버튼 | 씬 로더 교체 | 씬 로더 바꾸기, 씬 로더 바꿈 |

## 2. 끝맺음 규칙

공통:

- 메뉴, 버튼, 탭, 레이블, 열 제목, 배지, 상태 표시는 짧은 명사구로 쓴다.
- 설명이나 사실을 전달하는 문장은 합니다체로 쓴다. 문장 끝의 `~함`, `~됨`, `~필요`, `~불가`, `~여야 함`, `~아님`, `~중` 같은 전보체를 쓰지 않는다. 레이블과 짧은 상태인 `저장됨`, `시작 중`, `읽기 실패`는 그대로 쓸 수 있다.
- 한다체 서술 종결(`~한다`, `~이다`)을 쓰지 않는다.
- 문장이 둘 이상이면 문장마다 마침표를 찍는다. 한 문장짜리 짧은 알림과 레이블에는 마침표를 찍지 않아도 된다.
- 변수 뒤에 받침에 따라 바뀌는 조사(은/는, 이/가, 을/를, 와/과, 으로/로)를 두지 않는다. `을(를)` 같은 표기도 쓰지 않는다. 콜론으로 나누거나 `파일`, `값`, `타입` 같은 명사를 넣거나 문장 순서를 바꾼다. 의, 에, 에서, 만, 도는 그대로 쓸 수 있다.
  `${path} 을(를) 읽지 못했다` → `파일을 읽지 못했습니다: ${path}`
- 값 표기: 현재 값 `(현재: v)`, 현재 타입 `(현재 타입: t)`, 허용 값 `(허용: a, b)`.
- 코드 식별자, 경로, 키(props, play.maps, events[3])는 그대로 쓴다.
- 확인 대화상자의 사실과 결과는 합니다체로 쓰고, 질문은 `~할까요?`로 쓴다.
- 생성되는 스크립트 파일 안의 코드 주석(새 스크립트 템플릿, 샘플 프로젝트의 스크립트)은 문장형을 유지한다. 해당 리터럴에는 `// terms-ok:` 주석을 단다 (3절).

| 종류 | 형식 | 예 |
|---|---|---|
| 메뉴, 버튼, 탭, 레이블, 열 제목, 배지, 상태 표시 | 짧은 명사구 | `스크립트 추가`, `저장 안 됨`, `시작 중`, `일치 3개` |
| 빈 상태 표시 | 명사구 한 줄. 안내가 더 필요하면 뒤에 합니다체 한 문장 | `열린 프로젝트 없음`, `추가된 스크립트 없음. 인스펙터에서 스크립트를 추가할 수 있습니다.` |
| 알림, 콘솔의 짧은 결과 | 콜론 뒤에 값이 오는 짧은 결과는 명사구도 가능하다. 문장이면 합니다체로 쓴다 | `저장됨: tiles.json`, `파일을 저장하지 못했습니다: 디스크가 가득 찼습니다` |
| 오류, 경고, 검사 결과 | `<위치나 대상>: <문제>` 형식은 유지한다. 문제 부분이 문장이면 합니다체로 쓴다 | `id 중복: bg`, `speed: 0 이상이어야 합니다 (현재: -1)` |
| 확인 대화상자 | 사실과 결과를 합니다체로 쓰고 질문은 `~할까요?`로 쓴다 | `저장하지 않은 변경이 있습니다. 저장하지 않고 닫을까요?` |
| 툴팁, 도움말, 안내문 | 짧은 기능 이름은 명사구로, 설명은 합니다체로 쓴다 | `브러시로 찍습니다. 드래그하면 지나간 타일마다 찍습니다.` |
| aria-label | 같은 기능의 레이블과 같은 말을 쓴다 | `${name} 제거` |
| placeholder | 예시나 기본값을 쓴다. 선택하지 않은 상태는 `지정 안 함`으로 쓴다 | `지정 안 함 (기본값 60)` |

값 조건에서 기대 타입이 변수(TYPE_NAMES)일 때는 `타입 불일치: <타입>이어야 합니다 (현재: v)`를 쓴다. 파일이나 경로가 무엇인지 말할 때는 `지원하는 <종류>가 아닙니다: <경로>`처럼 쓴다 (`PNG 파일이 아닙니다: ${path}`).

## 3. 새 문구 검사

1. 문구가 가리키는 대상을 코드에서 확인한다 (타입 이름, 함수 이름, JSON 키). 용어표의 쓰는 말과 같은지 본다.
2. 종류(label, error 등)를 정하고 2절 형식에 맞춘다.
3. `yarn check:terms`로 쓰지 않는 말, 한다체 끝맺음, 확실하게 구분할 수 있는 전보체 끝맺음을 찾는다. CI의 웹 잡이 색 리터럴 검사 옆에서 같은 명령을 돌린다.

   ```sh
   yarn check:terms                                   # packages/*/src 와 src-tauri/src 전부
   node scripts/check-terms.mjs packages/ext-rpg/src  # 폴더나 파일 하나만
   ```

   - 보는 곳: `packages/*/src` 와 `src-tauri/src` 의 `.ts`, `.tsx`, `.mjs`, `.js`, `.rs`. TypeScript 파서로 문자열 리터럴, 템플릿 조각, JSX 텍스트와 속성만 꺼내므로 주석은 보지 않는다. Rust 는 줄 맨 앞의 `#[cfg(test)]` 모듈 앞까지 본다.
   - 보지 않는 곳: 테스트(`*.test.*`, `*.spec.*`, `test/`, `testing/`, `__fixtures__/`)와 JSON. `api-fallback.json` 의 설명은 엔진 `resources/api/initial2d-api.json` 과 같은 글이어야 하므로 엔진 쪽에서 규칙을 맞춘다.
   - 찾는 것: 1절 쓰지 않는 말 가운데 뜻이 하나로 정해지는 말(편집기, 판, 읽는 중, 칸, 붓, 폭, 그림, 표식, 여기서 실행, 웹판 같은 것. 목록은 스크립트의 `BANNED`), 한 낱말이 `-다`로 끝나는 한다체 끝맺음, 조건형 `~여야 함`, 둘째 문장 이후의 전보체 끝맺음이다. 합니다체(`-니다`), 요청(`-세요`), 질문(`-까요?`)은 허용한다. 결과는 `파일:줄: 이유: 줄 내용`이고 하나라도 있으면 종료 코드 1이다.
   - 예외: 그 줄 끝에 `// terms-ok: <이유>` 를 적는다. 여러 줄 템플릿 리터럴은 시작 줄이나 끝 줄(닫는 백틱 뒤)에 적는다. 생성하는 스크립트의 주석, 셸 명령처럼 규칙이 맞지 않는 문구에만 쓰고 이유를 함께 적는다.

4. 테스트에 같은 문구가 있으면 함께 바꾼다. `not.toContainText` 같은 부정 단언은 소스만 바꾸면 검사 없이 통과하므로 반드시 테스트 쪽 문자열도 바꾼다. 문구 사본을 상수로 들고 비교하는 e2e(예: `map-objects.spec.ts` 의 `rule`, `web-folder.spec.ts` 의 `SAMPLE_MAP_HINT`)도 찾는다. 문구를 바꿔 쓰이지 않게 된 도우미 함수(예: `validate.ts` 의 `subject`)는 함께 지운다 (`noUnusedLocals`).
5. 엔진과 글자 단위로 같아야 하는 문구는 엔진 저장소와 한 번에 바꾸고, 에디터는 `engine-pin.json` 을 그 커밋으로 올린 뒤 사본을 다시 받는다.
   - `packages/ext-rpg/src/model/validate.ts`, `game.ts`, `play.ts` 의 엔진 검사 문구: 엔진 `scripts/lua/rpg/commands.lua`, `mapdata.lua`, `assets.lua`, `scripts/lua/games/rpgdemo/config.lua`, `playenv.lua`. `yarn test:engine-events` 가 대조한다
   - 이벤트 커맨드 라벨: 엔진 `resources/schema/event-commands.json` (에디터의 사본은 `yarn sync:rpg` 로 받는다)
   - API 설명: 엔진 `resources/api/initial2d-api.json`. 에디터의 `api-fallback.json` 은 같은 항목에 같은 글을 쓴다
