# UI 용어와 문구 규칙

에디터 화면, 알림, 콘솔, 오류에 쓰는 말을 정한다. 같은 대상은 어디서나 같은 말로 부르고, 비유 대신 코드가 부르는 대상의 이름을 쓴다.

기준 예: `이 타입은 칸이 없다` → `추가 속성 없음`

## 1. 용어표

### 맵

| 대상 | 쓰는 말 | 쓰지 않는 말 |
|---|---|---|
| 레이어 data 의 한 요소 (gid 하나) | 타일 (개수는 `타일 N개`, 크기는 `WxH 타일`) | 칸, 셀 |

| 팔레트에서 고른 gid 직사각형 (Brush) | 브러시 | 붓, 붓 무늬 |

## 2. 끝맺음 규칙

공통:

- 한다체 서술 종결(-다)을 쓰지 않는다. 명사형으로 끝낸다: 없음, 있음, 실패, 불가, 미지원, 필요, ~여야 함, ~ 중, ~됨, 아님.
- 끝에 마침표를 찍지 않는다. 문장이 둘 이상이면 문장 사이에만 찍는다.
- 변수 뒤에 받침에 따라 바뀌는 조사(은/는, 이/가, 을/를, 와/과, 으로/로)를 두지 않는다. 콜론으로 나누거나 `값`, `타입` 같은 명사를 넣는다. 의, 에, 에서, 만, 도는 그대로 쓴다.
  `${o.id}: ${f.label} 은(는) 글이어야 한다` → `${o.id}: ${f.label} 값은 문자열이어야 함`
- 값 표기: 현재 값 `(현재: v)`, 현재 타입 `(현재 타입: t)`, 허용 값 `(허용: a, b)`.
- 코드 식별자, 경로, 키(props, play.maps, events[3])는 그대로 쓴다.
- 확인 대화상자의 질문 어미는 `~할까요?` 하나다.
- 생성되는 스크립트 파일 안의 코드 주석(새 스크립트 템플릿, 샘플 프로젝트의 스크립트)은 문장형을 유지한다. 해당 리터럴에는 `// terms-ok:` 주석을 단다 (3절).

| 종류 | 형식 | 예 (전 → 후) |
|---|---|---|
| label | 명사구. 되돌리기 이름은 `<대상> <동작>: <값>` | `글자` → `텍스트`, `스크립트 붙이기: ${name}` → `스크립트 추가: ${name}` |
| button | 추가, 삭제, 삽입, 이동, 선택, 편집. 표준 메뉴 동사는 ~기 (이름 바꾸기, 다시 읽기, 덮어쓰기, 붙여넣기, 만들기) | `내 것으로 덮어쓰기` → `편집 내용으로 덮어쓰기`, `빼기` → `삭제` |
| empty-state | `<무엇> 없음`, 안내가 필요하면 `. <조작>하면 <결과>` | `이 타입은 칸이 없다` → `추가 속성 없음`, `씬을 열면 여기에 오브젝트가 보인다` → `활성 씬 탭 없음` |
| status | 명사구. 진행은 `~ 중`, 결과는 `~됨` | `엔진 띄우는 중` → `엔진 시작 중`, `끝남` → `종료됨` |
| problem | `<위치>: <사실 또는 조건>`. 조건은 `~여야 함`, 중복은 `<대상> 중복: v` | `id 가 겹친다: ${o.id}` → `id 중복: ${o.id}`, `${min} 이상이 아니다 (지금은 ${v})` → `${min} 이상이어야 함 (현재: ${v})` |
| error | `<동작> 실패: <원인>`, `<동작> 불가 (<이유>)`, `<기능> 미지원`, `<대상> 없음: <값>` | `${path} 을(를) 읽지 못했다: ${e}` → `${path} 열기 실패: ${e}`, `루트는 지울 수 없다` → `프로젝트 루트 삭제 불가` |
| notice | 완료는 `~됨: <값>` (고유어 동사는 `다시 읽음`, `덮어씀`), 경고는 `<사실>, <결과>` | `저장했다: ${t}` → `저장됨: ${t}`, `하나만 둘 수 있는 타입이라 붙이지 않았다: ${l}` → `맵당 1개만 허용되는 타입이라 붙여넣기 제외: ${l}` |
| console | notice 와 같다. 머리말 `엔진 시작:`, `핫 리로드:`는 쓴다 | `밖에서 바뀌어 다시 읽었다: ${p}` → `외부에서 변경되어 다시 읽음: ${p}` |
| confirm | `<사실>. <결과>. <동작>할까요?` | `${t} 에 저장하지 않은 변경이 있다. 저장하지 않고 닫을까?` → `${t}: 저장하지 않은 변경 있음. 저장하지 않고 닫을까요?` |
| tooltip | 기능 설명은 명사구. 비활성 이유는 빠진 조건을 `~ 없음`으로. API 설명의 참 거짓 반환은 `~이면 true` | `붓을 찍는다. 끌면 선을 따라 찍는다` → `브러시 찍기. 드래그하면 지나간 타일마다 찍기`, `프로젝트를 먼저 연다` → `열린 프로젝트 없음` |
| aria | label 과 같다 | `${name} 떼기` → `${name} 제거` |
| placeholder | 예시나 기본값. 선택하지 않은 상태는 `지정 안 함` | `비움 (기본 ${d})` → `지정 안 함 (기본값 ${d})` |
| other | 도움말은 명사구를 마침표로 잇는다 | `F5 가 어디서 게임을 돌릴지.` → `F5로 게임을 실행할 위치` |

값 조건에서 기대 타입이 변수(TYPE_NAMES)일 때는 `타입 불일치: <타입> 필요 (현재: v)`를 쓴다. 파일이나 경로가 무엇인지 말할 때는 `<종류>가 아님: <경로>`를 쓴다 (`PNG 파일이 아님: ${path}`).

## 3. 새 문구 검사

1. 문구가 가리키는 대상을 코드에서 확인한다 (타입 이름, 함수 이름, JSON 키). 용어표의 쓰는 말과 같은지 본다.
2. 종류(label, error 등)를 정하고 2절 형식에 맞춘다.
3. `yarn check:terms` 로 쓰지 않는 말과 한다체 끝맺음을 찾는다. CI 의 웹 잡이 색 리터럴 검사 옆에서 같은 명령을 돌린다.

   ```sh
   yarn check:terms                                   # packages/*/src 와 src-tauri/src 전부
   node scripts/check-terms.mjs packages/ext-rpg/src  # 폴더나 파일 하나만
   ```

   - 보는 곳: `packages/*/src` 와 `src-tauri/src` 의 `.ts`, `.tsx`, `.mjs`, `.js`, `.rs`. TypeScript 파서로 문자열 리터럴, 템플릿 조각, JSX 텍스트와 속성만 꺼내므로 주석은 보지 않는다. Rust 는 줄 맨 앞의 `#[cfg(test)]` 모듈 앞까지 본다.
   - 보지 않는 곳: 테스트(`*.test.*`, `*.spec.*`, `test/`, `testing/`, `__fixtures__/`)와 JSON. `api-fallback.json` 의 설명은 엔진 `resources/api/initial2d-api.json` 과 같은 글이어야 하므로 엔진 쪽에서 규칙을 맞춘다.
   - 찾는 것: 1절 쓰지 않는 말 가운데 뜻이 하나로 정해지는 말(칸, 붓, 폭, 가로, 그림, 표식, 구역, 여기서 실행, 에디터 안, 웹판, 고르다, 끌다, 넣다, 옮기다 같은 것. 목록은 스크립트의 `BANNED`)과 한 낱말이 -다 로 끝나는 한다체 끝맺음(조사 보다, 마다는 뺀다). 결과는 `파일:줄: 이유: 줄 내용` 이고 하나라도 있으면 종료 코드 1 이다.
   - 예외: 그 줄 끝에 `// terms-ok: <이유>` 를 적는다. 여러 줄 템플릿 리터럴은 시작 줄이나 끝 줄(닫는 백틱 뒤)에 적는다. 생성하는 스크립트의 주석, 셸 명령처럼 규칙이 맞지 않는 문구에만 쓰고 이유를 함께 적는다.

4. 테스트에 같은 문구가 있으면 함께 바꾼다. `not.toContainText` 같은 부정 단언은 소스만 바꾸면 검사 없이 통과하므로 반드시 테스트 쪽 문자열도 바꾼다. 문구 사본을 상수로 들고 비교하는 e2e(예: `map-objects.spec.ts` 의 `rule`, `web-folder.spec.ts` 의 `SAMPLE_MAP_HINT`)도 찾는다. 문구를 바꿔 쓰이지 않게 된 도우미 함수(예: `validate.ts` 의 `subject`)는 함께 지운다 (`noUnusedLocals`).
5. 엔진과 글자 단위로 같아야 하는 문구는 엔진 저장소와 한 번에 바꾸고, 에디터는 `engine-pin.json` 을 그 커밋으로 올린 뒤 사본을 다시 받는다.
   - `packages/ext-rpg/src/model/validate.ts`, `game.ts`, `play.ts` 의 엔진 검사 문구: 엔진 `scripts/lua/rpg/commands.lua`, `mapdata.lua`, `assets.lua`, `scripts/lua/games/rpgdemo/config.lua`, `playenv.lua`. `yarn test:engine-events` 가 대조한다
   - 이벤트 커맨드 라벨: 엔진 `resources/schema/event-commands.json` (에디터의 사본은 `yarn sync:rpg` 로 받는다)
   - API 설명: 엔진 `resources/api/initial2d-api.json`. 에디터의 `api-fallback.json` 은 같은 항목에 같은 글을 쓴다
